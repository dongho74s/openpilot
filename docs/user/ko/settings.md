carrotpilot의 세부 설정은 **Carrot Web에서 모두 확인하고 변경하는 것**을 기준으로 합니다. 장치 자체의 기본 설정 화면은 Wi-Fi, 장치 정보, openpilot 기본 토글과 소프트웨어 업데이트에 사용하고, 아래에서 설명하는 `carrot_settings.json`의 파라미터는 Carrot Web의 **설정** 화면에서 관리합니다.

주행 중 가속도센서로 1.5g 이상의 수평 충격이 의심되면 경고와 10초 취소 안내를 표시합니다. 터치가 없으면 `OpenpilotEnabledToggle`을 꺼짐으로 저장하고 Dashcam 모드로 재부팅하며, 다시 켤 때까지 제어를 사용할 수 없습니다. [감지 조건·취소·복구와 녹화 공백](dashcam-log-sharing.md#충격-의심-시-자동-dashcam-모드)을 확인하세요.

주행 모델(콤마 자체 GPU로 돌리는 내장 모델)은 설정 화면이 아니라 **도구 → 주행 모델 카드**에서 바꿉니다. 주차하고 시동을 끈 상태에서만 바꿀 수 있고, 다음 주행부터 적용됩니다. 자세한 내용은 [Carrot Web 안내](carrot-web.md#주행-모델-바꾸기-내장-모델)를 보세요.

## Carrot Web 접속

**속도·감속 → 과속카메라 → Navdy 연결 방식**에서 `기존 설정`, `유선 USB`, `무선 Bluetooth`를 선택할 수 있습니다. 유선은 콤마 직접 USB 또는 등록된 Jetson의 USB 경유만 사용하며 블루투스로 자동 대체하지 않습니다. 무선에서는 USB를 진단용으로 연결해도 데이터는 Bluetooth로 보냅니다. 폰 자동 재연결·앰비언트 연결과 내비 입력 선택은 유지됩니다. 연결 변경은 잠시 안내 데이터를 끊으므로 주차 중 변경하세요. 새 설정이 포함된 최초 업데이트는 정상 빌드와 재시작이 필요하며, 이후에는 약 5초 주기와 진행 중인 연결 시도 종료 후 반영됩니다.

이 이식 브랜치는 `CarrotNaviSource`를 추가합니다. **속도·감속 → 내비 입력 선택**의 `0`은 기존 네트워크, `1`은 Navdy입니다. 저장 후 재부팅해야 적용됩니다. 기본 정책은 직접 USB를 우선하며, 없으면 설정된 블루투스 기기와 등록된 Jetson을 시도합니다. USB가 다시 연결되면 USB로 돌아갑니다. 별도로 `bluetooth_only`를 설정한 기기는 진단용 USB가 연결되어도 데이터는 블루투스로만 송수신합니다. 호환 Navdy 앱과 사전 페어링이 필요하며 Git 업데이트만으로 APK 설치나 페어링이 되지는 않습니다. [블루투스 설정](../../../tools/navdy/BLUETOOTH.md)을 참고하세요. Navdy 선택 시 네트워크 안내로 자동 대체하지 않으며 음악·시각 동기화는 유지합니다. [수신 조건과 만료 처리](speed-deceleration.md#navdy-input)를 확인하세요.

1. comma 장치와 휴대폰 또는 PC를 같은 네트워크에 연결합니다.
2. 브라우저에서 `http://장치-IP:7000`을 엽니다.
3. 상단 메뉴에서 **설정**을 선택합니다.

예를 들어 장치 IP가 `192.168.0.25`라면 다음 주소를 사용합니다.

    http://192.168.0.25:7000

접속 문제와 다른 화면의 설명은 [Carrot Web](https://github.com/ajouatom/openpilot/wiki/Guide-Carrot-Web)을 참고하세요.

### 웹 화면 구성 기본값

`도구 > Web Settings > 화면 구성`의 처음 설치 기본값은 가로·세로 모두 **영역 1 전체**이며, 영역 1은 **당근비전**, 영역 2는 **당근네비**입니다. `기본값` 버튼은 두 방향을 모두 **영역 1 전체 + 영역 1 당근비전 + 영역 2 당근네비**로 되돌립니다. 화면별 설명은 [Carrot Web 화면 구성](carrot-web.md#화면-구성)을 참고하세요.

## 설정 화면 사용법

### C4 화면 선택: new ui

**화면 → 정보 표시 → new ui** (`NewUi`)는 0~3 중에서 고르며 기본값은 0입니다. 0은 기존 당근 UI, 1은 아래에 설명한 Wayon/sunnypilot 스타일 화면(아래 설명의 'ON'), 2는 시계, 3은 로봇 얼굴입니다. 예전에 ON으로 켜 둔 값은 1로 그대로 유지됩니다. C3·C3X에서는 1만 적용되며 아래 "C3·C3X 화면" 절의 v10-nui 화면이 나옵니다.

new ui의 차선과 도로 경계는 종류·인게이지·조향 토크에 따른 색 전환 없이 흰색 실선으로 표시합니다. 인식 신뢰도에 따른 투명도와 차선 위치는 유지하며, 가운데 주행 경로와 앞차 하단 바의 색은 변경하지 않습니다. 나브디에는 기존 실선·점선·차선 종류 정보를 그대로 전달합니다. OFF에서는 기존 C4 표시로 돌아갑니다.

ON에서는 536×240 화면 전체를 사용합니다. 오른쪽 confidence ball과 신호등 표시를 숨기고 전용 60px 영역을 없앱니다. 카메라·차선·앞차 표시·BSM·HUD가 확장된 폭을 함께 사용합니다. OFF로 바꾸면 기존 476px 카메라 영역과 오른쪽 상태 표시가 복원됩니다. 화면 표시만 변경하며 신호등 인식·경고·제어 동작은 그대로입니다.

**화면 → 정보 표시 → new ui** (`NewUi`)는 기본 OFF입니다. ON이면 C4 온로드 화면에 Wayon/sunnypilot 스타일의 하단 핸들·토크 바와 변경 후 약 2.5초 동안의 MAX 설정속도를 표시합니다. 큰 상시 속도·기어·디버그 패널과 VISION 상태 카드는 숨기지만 카메라·차선·주변 차량·레이더/비전 앞차 표시·사각지대 경고·주차/홀드 타이머·주요 경고는 유지합니다. DM 표시는 왼쪽 위로 옮기며 MAX·타이머·경고 중에는 겹치지 않게 숨깁니다. 조향만 활성인 경우도 초록 핸들로 표시합니다. 크루즈 간격·주행 모드·NAVI 연결 문구·감속 목표 숫자와 기존 원인 패널은 숨기며, 해당 정보가 필요하면 OFF를 사용합니다.

앞차 사각형 대신 차량 하단의 투영 위치에 끝이 둥근 3px 바를 표시합니다. 레이더가 결합된 앞차는 초록색 `#20D86A`, 비전만으로 인식한 앞차는 밝은 파랑 `#50BEFF`이며, 거리 변화에 따라 폭이 24–140px 안에서 바뀝니다. 나타날 때 0.18초, 사라질 때 0.20초 동안 페이드하며, 인식이 없어지거나 데이터가 오래되면 계속 남겨두지 않습니다. 세션·레이아웃 변경이나 오프로드 전환 시에는 옛 표시를 지웁니다. 색은 인식 출처이며 인게이지·제동 여부가 아닙니다. `ShowRadarInfo`는 이 주 앞차 표시를 끄지 않습니다. OFF에서는 기존 사각형이 유지되고, 나브디 전송·감지·제어 입력은 바뀌지 않습니다.

선택된 감속 사유는 핸들 오른쪽·토크 바 위의 작은 사각 배지(`TURN`, `CAM`, `BUMP`, `SECTION` 등)로 표시합니다. 모서리만 살짝 둥글고 내부는 색으로 채웁니다. 종방향 제어가 활성이고 최신 계획에 해당 속도 제한이 실제로 적용될 때만 표시하며, 미적용 후보는 숨깁니다. 적용 중에는 초록/흰색으로 1초 주기 점멸하고 짙은 글자는 계속 표시됩니다. 이는 속도 제한 적용 표시이지 브레이크 작동 여부가 아닙니다. 적용이 끝나거나 가속·브레이크로 수동 개입하면 즉시 숨기며, 다시 적용되면 초록색부터 시작합니다. 전체 후보 목록이 아니라 현재 선택된 사유 하나를 표시하며, 오래된 내비 데이터·경고·정차 타이머 중에는 숨깁니다.

BSM은 Wayon 원본 주황색 차량 이미지(108×128, 본문 좌우 여백 20px, y=100)와 0.15초 시정수의 페이드 필터를 사용합니다. new ui에서만 기존 가장자리 막대와 도로 위 BSM 벽을 대체합니다. 차량 자체·비전 감지는 기존 carState의 통합 신호를 그대로 사용하며 이 화면에서는 출처별 색을 구분하지 않습니다. BSM 표시 중에는 조향만 활성인 경우도 일반 핸들 대신 BSM이 나타나고, 토크 표시는 유지합니다. 왼쪽 BSM은 일시적인 MAX보다 우선하며 감속 배지는 겹치지 않는 x=136에 고정합니다. 중요한 조향 경고와 주차/홀드 타이머 중에는 BSM 이미지를 숨겨 해당 표시가 우선합니다. carState 무효·수신 중단·이전 세션이면 옛 경고가 남지 않도록 즉시 지웁니다. 감지·제어 로직은 변경하지 않습니다.

DM은 눈 캐릭터·상태 글자 대신 Wayon 원본의 사람 실루엣·시선 방향 표시를 사용합니다. 왼쪽 16px·위 10px의 60×60 영역에 표시하며, 기존 감시 상태에 따라 초록/주황으로 바뀌고 휴대폰 감지 시 원본 휴대폰 아이콘으로 전환됩니다. 이전 세션·0.5초 이상 오래되거나 멈춘 데이터·카메라/얼굴 인식 상실 시 초록 시선과 휴대폰 표시는 남기지 않습니다. NewUi OFF의 기존 DM 표시는 유지하며(C3·C3X의 1번 DM은 아래 절 참고) 감시 판단·경고·소리·인게이지 조건은 변경하지 않습니다.

**2 (시계)**: 주행 중 C4 화면에서 카메라·차선·속도 패널·DM 표시를 모두 끄고 가로로 넓은 아날로그 시계만 표시합니다. 시각은 한국 시간이며, 바깥 테두리를 따라 분 눈금과 시 눈금, 12·3·6·9 숫자, 시침·분침과 흘러가는 초침이 있습니다. 왼쪽에는 핸들 아이콘과 현재 속도, 오른쪽에는 요일(영문)과 날짜를 표시합니다. 핸들 아이콘은 조향 중이면 초록, 아니면 회색입니다. 해가 진 뒤에는 화면 전체가 빨간 야간 모드로 바뀌고 초침을 숨깁니다. 야간 모드에서는 조향 중이면 핸들 아이콘이 밝은 빨강, 아니면 어두운 빨강입니다. 야간 판단은 나브디 앰비언트와 같은 해 높이 기준입니다. 서울 기준으로 해가 지평선 아래 4° 이하로 내려가면(해 진 뒤 약 20분) 야간, 새벽에 -3° 위로 올라오면 주간이며, 바뀔 때 약 1초에 걸쳐 색이 서서히 변합니다. 카메라 노출은 밤에도 낮의 흐린 구간과 비슷하게 나와서 쓰지 않으므로, 낮 터널이나 지하 주차장에서는 바뀌지 않습니다. 시동을 건 직후에는 그 시각에 맞는 모드로 바로 시작하고, 콤마 시계가 아직 맞춰지지 않았으면 주간으로 둡니다. 정차 타이머·오토홀드 타이머는 띄우지 않고, 그 자리를 대신 차지하던 저순위 안내(주차 브레이크, 브레이크 홀드, 재출발 필요, 저속 조향 안내)도 정차 중에는 숨깁니다. 정차 시간은 뒤에서 계속 세므로 1로 바꾸면 실제 경과 시간이 나옵니다. 다른 경고와 위험 경고는 시계 위에 그대로 뜹니다. 화면 표시만 바꾸며 경고 판단·소리·주행 제어는 그대로입니다.

**3 (로봇 얼굴)**: 주행 중 C4 화면에서 카메라·차선·속도 패널·DM 표시를 끄고, 빛나는 둥근 사각 눈 두 개가 차 상태에 따라 표정을 바꿉니다. 눈 색으로 상태를 구분합니다: 평소 주황, 인게이지(주행) 초록, 걱정·힘쓰기 호박색, 위험 빨강. 눈은 늘 숨 쉬듯 움직이고, 2~6초마다 깜빡이며, 아무 일 없을 때는 갸웃·눈맞춤·윙크·두리번·선글라스·하트 눈 같은 버릇을 합니다. 인게이지되면 깡충 뛰며 별눈이 된 뒤 화면 아래에서 핸들이 올라오고, 로봇 손 두 개가 핸들을 잡은 채 실제 핸들 방향으로 돌립니다. 차로 유지처럼 작은 각도도 보이도록 작은 각도는 약 세 배로 크게 보여 주고, 바깥쪽 손이 화면 밖으로 나가지 않는 약 9°까지만 돕니다(그 이상은 부드럽게 멈춤). 입은 핸들과 겹치지 않게 늘 핸들 위에 그립니다. 운전자가 핸들을 돌리거나, 이 차가 조향할 수 없는 저속(10 km/h 아래)이 되면 손을 핸들에서 떼고 들어 올립니다. 조향이 돌아오면 다시 잡습니다. 레인모드로 조향하는 동안(`controlsState.activeLaneLine`, 속도·앞차·곡률 조건이 모두 반영된 실제 값)은 핸들 테에 색이 채워지고, 레인리스면 비어 있습니다. 레인모드가 되면 두 손에서 색이 테를 따라 번지고, 두 줄기가 12시 표시에서 만나며 번쩍이고, 손을 꽉 쥐듯 잠깐 커집니다. 다른 반응이 없으면 핸들을 한번 내려다보고 끄덕입니다(8초에 한 번까지). 채워져 있는 동안 색이 숨 쉬듯 밝아졌다 어두워지고 3.6초마다 빛 한 줄기가 테를 훑습니다. 레인리스로 바뀌면 색이 손 쪽으로 빨려 들어가며 비워집니다. 화면 가장자리 아이콘이나 운전자 감시 표시는 띄우지 않고, 표정과 몸짓으로만 반응합니다. 주행을 시작하면 눈을 뜨며 깡충 뛰고 반짝이고, 차선 변경 때는 그쪽으로 기울었다가 끝나면 두 번 끄덕입니다. 사각지대에 차가 있으면 흠칫 물러나 그쪽을 노려보며 느낌표가 뜨고, 앞차가 출발하면 눈이 커지며 느낌표가 뜹니다. 끼어들기에는 움찔 물러나며 빠르게 두 번 깜빡이고, 가속 페달을 밟으면 운전자 쪽을 보며 갸웃하고 물음표가 뜹니다. 저속이라 조향이 꺼지면 운전자 쪽으로 꾸벅하고, 급커브에서는 바깥으로 쏠리며 바람 줄기가 지나갑니다. 급제동이나 전방 충돌 경고에는 눈이 빨개지며 느낌표가 뜨고, 운전자 감시 경고가 풀리면 휴~ 하고 입김을 냅니다. 그 밖에 반응하는 이벤트: 주행 중 안전벨트 미착용(운전자 쪽을 걱정스럽게 봄, 풀려 있는 동안 30초마다), 후진 기어(아래를 보며 삐삐), 주차 기어(웃으며 인사하고 한숨), 비상등(살짝 빨간 눈으로 걱정), 운전자의 핸들 개입(잠깐 손을 떼고 운전자를 봄, 15초에 한 번까지, 차선 변경 중에는 생략). 로봇이 직접 쓰거나 드는 소품도 있습니다. 폰에서 노래가 재생되는 동안 헤드폰을 쓰고, 비상등이 켜져 있는 동안 머리 위에 빨간 경광등이 돌며 번쩍입니다. 운전자 감시 경고 중에는 호루라기를 물고 짧게 불고, 안전벨트가 풀리면 운전자 쪽 손으로 벨트 버클을 들어 흔듭니다(그동안 핸들을 잡은 왼손은 핸들에서 빠집니다). 내비 데이터(과속카메라·제한속도, 회전 안내, 과속방지턱, 목적지 도착)에는 반응하지 않고 차와 운전자 상태에만 반응합니다. 크루즈 설정속도는 인게이지할 때(깡충 별눈 뒤)와 인게이지 중 바뀔 때 크게 보여 줍니다. 눈이 먼저 가로줄로 감기고, 그 자리에 큰 숫자가 뜹니다. 인게이지 때는 숫자가 한 자리씩 위에서 떨어지고, 바꿀 때는 바뀐 자리만 주행거리계처럼 굴러갑니다(올리면 위로 구르며 초록, 내리면 아래로 구르며 호박색, 숫자 위에 화살표). 2.4초 뒤(계속 바꾸면 마지막 변경부터) 숫자가 작아지며 사라지고 눈을 다시 뜹니다. 눈과 숫자가 함께 그려지는 순간은 없습니다. 급제동·운전자 감시 경고·사각지대·안전벨트·인게이지 해제처럼 눈이 필요한 반응이 오면 숫자는 바로 비켜 줍니다. 45초 넘게 정차하면 졸다가 잠옷 모자를 쓴 채 잠들고, 출발하면 깨어납니다. 앞차가 출발하거나 노래가 나오면 자다가도 깹니다. 조향 토크가 셀수록(차 한계의 50%부터, 95%에서 최대) 점점 더 힘을 줍니다. 눈을 가늘게 뜨고 이를 악물고 떨며 핸들 손도 떨리고, 한계 근처에서는 눈을 질끈 감습니다(>_<). 폰에서 노래가 실제로 재생되는 동안(Navdy HUD v186 이상이 폰 플레이어의 재생 상태만 콤마에 알려 주고, 곡 제목·가수는 보내지 않습니다. 곡 정보가 떠 있어도 일시정지·정지 상태면 춤추지 않고, 재생 상태가 1.5초 이상 이어져야 시작하며 멈추면 바로 그칩니다) 고개를 까딱이며 음표를 띄우고 리듬을 탑니다. 마이크가 박자를 잡으면 그 박자를 따르고, 못 잡으면 1분에 120박으로 탑니다. 재생 중에는 졸지 않습니다. 더 중요한 반응(운전자 감시 경고, 급제동이 가장 먼저)이 나오는 동안 생긴 반응은 1~5초 기다렸다가 이어서 나오고, 그 안에 차례가 안 오면 버립니다. 같은 반응은 몇 초에서 수십 초 안에 반복하지 않습니다. 정차·오토홀드 타이머와 일반·안내 경고창은 얼굴 위에 띄우지 않습니다(로봇이 대신 반응하고, 경고음은 그대로 납니다). 빨간 위급 경고만 얼굴 위에 뜹니다. 화면 표시만 바꾸며 경고 판단·소리·주행 제어는 그대로입니다.

변경은 약 0.5초 주기로 재부팅 없이 반영되고 0으로 되돌리면 기존 당근 UI가 복원됩니다. C3·C3X는 아래 절의 1번 화면 외에는 바뀌지 않고, 외장 계기판, 오프로드 인사/요약 화면 및 조향·제동·운전자 감시 판단은 바꾸지 않습니다. 새 설정 키가 포함된 첫 업데이트는 정상 빌드를 마쳐야 합니다.

### C3·C3X 화면: new ui 1 (v10-nui)

C3·C3X에서는 `NewUi`가 1일 때만 carrotpilot `v10-nui` 브랜치의 주행 화면(FrogPilot testing-v1 디자인)으로 바뀝니다. 화면 그림은 오프로드에서 미리 준비하며, 주행 중 1로 바꾸면 준비가 끝나는 동안(보통 1초 이내) 기존 화면을 보여 준 뒤 바뀝니다. 0·2·3이면 기존 당근 화면이 그대로 나옵니다(2 시계, 3 로봇 얼굴은 C4 전용입니다).

- 카메라를 화면 전체에 그리고 화면의 네 꼭짓점을 둥글게 깎습니다. 사이드바를 열면 사이드바까지 포함한 화면 전체의 바깥 모서리를 둥글게 하고, 사이드바와 카메라가 맞닿는 쪽은 각진 채 이어지며, 화면 전체 경고 위에도 적용됩니다. 상태 테두리·당근 속도 패널·내비 안내·디버그 글자·실험 모드 버튼은 숨깁니다. 위쪽은 살짝, 아래쪽은 HUD가 잘 보이도록 점점 어둡게 덮습니다. 카메라 영상이 화면보다 작은 C3X(1344×760)도 화면을 꽉 채우도록 확대하고, 차선·경로·앞차 표시는 영상과 같은 배율로 그려 실제 도로 위에 겹칩니다(0·2·3의 기존 화면은 그대로).
- 아래쪽 가운데에 현재 속도와 단위(KM/H·MPH), 오른쪽에 차간 단계 아이콘(주행 성향 1~4칸)과 `SET` 설정속도, 맨 오른쪽 아래에 핸들 아이콘이 있습니다. 핸들은 실제 조향각만큼 돌아가고, 조향 중에는 흰색에서 조향 출력이 커질수록 노랑·빨강으로 바뀌며, 운전자가 핸들로 개입하면 파랑입니다. 조향 한계 경고(`steerSaturated`)는 경고창 대신 커진 핸들과 왼쪽 위 빨간 느낌표로 표시합니다.
- 현재 속도 오른쪽의 LFA 아이콘은 인게이지 초록, 조향만 활성(인게이지 없이 조향 보조) 민트, 가속 페달 개입 파랑, 인게이지 가능 흰색, 그 밖은 회색입니다. 당근 내비 연동이 켜지면 차간 아이콘 위에 `APN` 배지가 뜹니다(연결 파랑, 과속카메라·구간단속 등 안내 중 초록).
- 방향지시등을 켜면 속도 양옆에 초록 화살표가 깜빡입니다. 사각지대에 차가 있으면 화면 좌우에 주황 차량 아이콘이 뜨고, 그쪽 방향지시등을 켜고 있으면 빠르게 깜빡입니다.
- 1분 넘게 정차하면 현재 속도 자리에 정차 시간(분:초)을 표시합니다.
- 차선은 흰색(인식 신뢰도만큼 투명), 도로 경계는 빨강입니다. 주행 경로는 평소 초록(가속 허용 여부가 바뀌면 0.5초 동안 색 전환), 실험 모드는 가감속 색, 조향만 활성은 민트, 차선 모드는 흰색이며 차선 모드에서는 내 차선 양쪽 선을 굵은 초록으로 표시합니다. 차선 변경 중에는 넘어가는 선을 숨기고 현재 차선과 목표 차선의 바깥 선을 민트로 강조합니다.
- 인게이지되지 않았고 조향 보조도 꺼져 있으면 카메라를 흑백으로 바꿔 62% 밝기로 낮추고, 차선을 숨기고 경로를 회색으로 그립니다.
- `ShowPathEnd`가 1 이상이면 앞차에 둥근 사각형을 그립니다(레이더 SCC 앞차 빨강, 그 밖의 레이더 앞차 주황, 비전만 파랑, 두 번째 앞차 갈색). 사각형 아래에 레이더 거리(빨강·주황)와 비전 거리(파랑)를 숫자로 표시합니다.
- 왼쪽 아래 DM 표시는 사람 실루엣과 시선 방향 원뿔입니다. 원뿔은 인게이지(조향만 활성 포함) 초록, 인게이지 가능 흰색, 그 밖은 회색입니다. 카메라 감시 중이 아니거나 감시 데이터가 0.5초 넘게 오래되면 흐리게 하고 방향을 가운데로 둡니다. 경고창이 뜨면 숨깁니다.
- 경고창: 작은 경고는 아래쪽 한 줄 높이 상자, 중간 경고는 두 줄 높이 상자, 큰 경고는 화면 전체입니다. 둘째 줄이 없는 경고는 한 줄 높이 상자로 표시합니다. 전방 추돌(FCW·AEB)과 차선 이탈(LDW) 경고는 화면을 어둡게 덮고 위쪽에 큰 아이콘을 깜빡입니다. 정지 상태 해제 필요(`resumeRequired`)는 화면을 어둡게 덮고 오토홀드 아이콘·경과 시간·안내 문구를 표시합니다. 정차 중 앞차가 출발하면(1~30m, 앞차가 0.8m/s 넘게 멀어짐) 3초 동안 "선행 차량이 출발하였습니다"를 화면 전체에 띄웁니다. 레이더 데이터가 끊기거나 유효하지 않으면 새로 띄우거나 연장하지 않습니다. 이 안내는 화면 표시만이며 소리는 없습니다.
- 주행 중 사이드바는 기본으로 숨겨져 있고, 화면을 누르면 열립니다. 연 뒤 10초 동안 사이드바를 건드리지 않으면 저절로 닫히고(사이드바를 누르는 동안에는 다시 10초를 셉니다), 다시 누르면 또 열립니다. 열려 있을 때 카메라 화면을 누르면 바로 닫힙니다. 0·2·3에서 열어 둔 채 1로 바꾸면 그때부터 10초를 셉니다. 0·2·3에서는 지금처럼 누를 때까지 열려 있습니다. 1을 다른 값으로 바꿨다가 돌아오거나 설정 화면을 열었다 돌아오면 정차·오토홀드 시간은 처음부터 다시 셉니다. 새 주행에서도 이전 주행의 오토홀드 시간은 이어지지 않습니다. 외부 HUD 연결 중 `ShowCameraWithCluster=0`이면 카메라 자리를 검게 두고 차선·경로를 그리지 않습니다.

v10-nui 브랜치는 경고 문구·크기·소리(selfdrived 이벤트)와 화면 밝기 처리도 바꿨지만, 이 설정은 화면 표시만 바꾸므로 그 부분은 가져오지 않았습니다. 경고 판단·소리·문구, 주행 제어, 운전자 감시 판단, 밝기, 오프로드 화면은 그대로이며 C4의 1번 화면도 바뀌지 않습니다.

Carrot Web 설정 화면에서는 다음 기능을 사용할 수 있습니다.

- **분류 탐색**: 대분류, 중분류, 세부 구역 순서로 설정을 찾습니다.
- **검색**: 화면 제목이나 파라미터 이름으로 원하는 항목을 찾습니다.
- **즐겨찾기**: 설정 항목을 길게 눌러 추가하거나 제거합니다.
- **프로필**: 현재 설정 묶음을 이름을 붙여 저장하고 다시 적용합니다.
- **설정 비교**: 프로필이나 백업의 값과 현재 값을 비교한 뒤 적용합니다.
- **초기화**: 전체 설정을 카탈로그 기본값으로 되돌립니다.
- **파일·QR 백업**: 도구 화면에서 설정을 보관하거나 복원합니다.

전체 초기화나 다른 차량의 백업 적용은 많은 값을 한꺼번에 바꿉니다. 먼저 현재 설정을 별도 프로필과 파일로 보관하세요.

### 항목별 상세 설명

설정 항목의 값 조절 부분을 제외한 본문을 누르면 해당 항목의 상세 화면으로 이동합니다. 기존 설정 박스 아래의 정보 박스에는 **설명**, **인기값**, **이력** 탭이 항상 표시되며 **설명**이 기본으로 열립니다. 데이터가 없는 탭도 사라지지 않고 빈 상태를 표시합니다.

- **설명**은 GitHub에서 검증·게시된 현재 언어의 설정 설명을 우선 표시합니다.
- 게시 인덱스와 설명 페이지의 해시가 모두 맞는 내용만 표시합니다.
- 요청이 실패하거나 내용이 올바르지 않으면 마지막으로 검증된 브라우저 저장본을 사용합니다.
- 검증된 원격 정상본이나 저장본이 없으면 장치 내부 문서로 대체하지 않고 빈 상태를 표시합니다.
- **인기값**은 수집된 차량의 값 분포를 참고용으로 표시하며 권장값을 뜻하지 않습니다.
- **이력**은 최근 변경 3건을 먼저 표시하고, 기록이 더 있으면 전체 이력을 열 수 있습니다.
- 네트워크나 문서 처리에 문제가 생겨도 설정값 확인·변경 기능은 계속 사용할 수 있습니다.
- Carrot Web이 한국어이면 한국어 원문, 영어이면 영어 원문을 표시합니다.
- 중국어 상세 원문이 아직 없으면 중국어 제목·짧은 설명은 유지하고 상세 설명만 영어로 표시합니다.
- GitHub Wiki의 우측 `사용 설명서 > 설정 이해하기 > 전체 설정`에서는 Carrot Web과
  같은 한국어 메뉴 계층·순서로 개별 설정 페이지를 찾을 수 있습니다. 중앙 전체 설정
  문서에서는 한국어·영어·중국어 목록을 함께 제공합니다.

가로·세로 화면 모두 기존 설정 박스 다음에 정보 박스가 세로로 이어집니다. 배율과 기본값 버튼의 위치와 동작은 기존 설정 박스 안에서 유지됩니다.

검증된 게시 설명은 현재 설정 코드의 기본값·범위·선택지를 기준으로 작성됩니다. 화면의 짧은 설명과 상세 설명이 다르면 현재 브랜치의 설정 코드와 함께 문제를 확인하세요.

## 숫자와 기본값 읽는 법

`carrot_settings.json`의 각 항목에는 다음 정보가 들어 있습니다.

| 필드 | 의미 |
|---|---|
| `name` | 코드와 Params에서 사용하는 고유 이름 |
| `title` | Carrot Web에 표시되는 한국어 제목 |
| `descr` | 값의 방향, 모드 번호와 주의사항 |
| `min` / `max` | 입력 가능한 범위 |
| `unit` | `+`와 `-` 버튼으로 한 번에 움직이는 단위 |
| `default` | 설정 카탈로그가 사용하는 초기 기준값 |

### 현재 값이 가장 우선입니다

2026 스타리아 EV는 차량 선택에서 `Hyundai Staria EV 2026`을 사용합니다. 기존 스타리아 선택은 자동 변경되지 않으며, HDA2·카메라 SCC 설정은 차량 배선에 맞춰 별도로 확인합니다. [차량 선택 안내](carrot-web.md#도구-화면)를 참고하세요.

업데이트 후에도 장치에 저장된 영구 설정은 유지될 수 있습니다. JSON의 `default`, 제목 괄호 안 숫자, 다른 사용자의 설정값보다 **내 장치의 Carrot Web에 표시된 현재 값**을 먼저 기록하세요.

`default`는 모든 차량에 권장되는 튜닝값이라는 뜻이 아닙니다. 차종 기본 튜닝, 기존 Params와 브랜치에 따라 실제 시작값이 다를 수 있습니다.

### 배율과 단위를 확인합니다

| 표시 예 | 저장값 | 실제 의미 |
|---|---:|---:|
| `TFollowGap1 x0.01s` | `110` | 1.10초 |
| `SteerActuatorDelay` | `30` | 0.30초 |
| `LateralTorqueAccelFactor x0.001` | `2500` | 2.500 |
| `StopDistanceCarrot` | `600` | 6.00m(600cm) 기준 값 |
| 비율 `%` | `105` | 105% |

항목 이름과 설명에 적힌 `x0.01`, `x0.001`, `cm`, `km/h`, `%`를 생략하면 값의 크기를 잘못 이해할 수 있습니다.

## 주행 제어

주행 제어는 차량 움직임에 영향을 줄 수 있는 123개 항목입니다. 한 번에 여러 값을 변경하지 마세요.

<a id="start-auto"></a>
### 시작·오토 — 9개

| 세부 구역 | 파라미터 | 용도 |
|---|---|---|
| 시작 동작 | `AlwaysLateral`, `AutoEngage`, `DisableMinSteerSpeed` | 상시 조향, 주행 시작 시 자동 활성화, 저속 조향 제한 |
| 오토크루즈 | `AutoCruiseControl`, `AutoGasTokSpeed`, `AutoGasCancelSpeed`, `AutoGasSyncSpeed`, `CruiseOnDist` | 크루즈 자동 활성화와 가속 페달 입력 시 동작 |

- `AlwaysLateral`: 크루즈가 켜져 있지 않아도 조향 제어를 허용합니다. 지원 Tesla 차량에서는 전진 기어의 실제 정차 상태에서도 조향할 수 있으며, 최소 조향 속도 이하로 이동할 때의 제한은 유지됩니다. [Tesla 제어 진입](tesla.md#engagement-and-standstill)을 참고하세요.
- 상시 조향도 시스템 시작 후 최초 준비 확인 전에는 조향하지 않습니다. 모델·차량 파라미터·자세 정보 등 필수 입력이 한 번 정상으로 확인되면 이 시작 검사는 종료되며, 이후 입력의 일시적 불량이나 조향 해제·재작동으로 다시 차단하지 않습니다. 기존 주행 중 안전 처리는 그대로 유지됩니다. 초기 대기시간 경과만으로 준비를 통과하지 않습니다.
- `AutoEngage`: `0` 끄기, `1` 조향 ON, `2` 조향 ON과 크루즈 대기입니다.
- `AutoCruiseControl`: 현대·기아 차량용 오토크루즈와 소프트홀드 관련 설정입니다.
- `WIP-FR`의 공통 크루즈 처리에서는 `AutoCruiseControl=0`일 때 페달을 놓아도 자동 활성화용 속도 선택으로 기존 설정속도를 바꾸지 않습니다. 이미 인게이지된 상태의 엑셀톡은 설정된 다음 속도 단계로 증속하며, 자동 인게이지를 켜지는 않습니다. SET/RES 버튼, 가속페달을 계속 밟을 때의 별도 `AutoGasSyncSpeed` 설정, 패들 및 도로·모델 속도 기능은 그대로 적용됩니다.
- `DisableMinSteerSpeed`: SMDPS 장착 차량의 저속 조향 제한과 관련된 차량별 설정입니다.

### 버튼·프리셋 — 16개

아래 표의 **세부 구역 제목을 누르면** 실제 코드 기준의 버튼 상태기계, 속도 단위와 적용 조건을 설명한 페이지로 이동합니다.

| 세부 구역 | 파라미터 | 용도 |
|---|---|---|
| [버튼 모드](buttons-presets.md#button-modes) | `CruiseButtonMode`, `NavigationSetSpeed`, `CancelButtonMode`, `LfaButtonMode`, `PaddleMode` | 크루즈, SET 진입 속도, 캔슬, LFA와 패들 버튼의 동작 지정 |
| [속도 단위](buttons-presets.md#speed-units) | `CruiseSpeedUnit`, `CruiseSpeedUnitBasic`, `CruiseButtonLongDelay` | 짧게·길게 누를 때의 속도 변경 단위와 판정 시간 |
| [버튼 테스트](buttons-presets.md#button-spam) | `CruiseButtonTest1`, `CruiseButtonTest2`, `CruiseButtonTest3` | 순정 SCC 목표속도 동기화용 버튼 메시지 값 |
| [속도 프리셋](buttons-presets.md#speed-presets) | `CruiseSpeed1`, `CruiseSpeed2`, `CruiseSpeed3`, `CruiseSpeed4`, `CruiseSpeed5` | 사용자3 모드에서 사용하는 속도 테이블 |

버튼 설정은 순정 SCC 사용 여부와 차량 버튼 메시지에 따라 체감이 크게 다릅니다. 버튼이 예상과 다르게 작동하면 사용자 모드보다 `CruiseButtonMode=0`의 일반 동작에서 먼저 확인하세요.

폭스바겐의 별도 `SET`은 현재 속도 설정, `RES`는 이전 설정속도 복원에 사용하고, `+`·`-`는 버튼 모드·속도 단위·길게 누르기 설정을 따릅니다. 오픈파일럿 종방향 제어의 수동 인게이지 버튼은 기존 물리 `SET`·`RES`로 유지됩니다.

`WIP-FR`의 `NavigationSetSpeed`를 켜면 SET 인게이지에 유효한 내비 제한속도 +10km/h(30 제한은 +5)와 현재속도 중 큰 값을 사용하는 [내비 기반 초기 설정속도](buttons-presets.md#button-modes)가 적용됩니다. 기본값은 꺼짐이며, 변경은 약 0.1초 내 반영되어 다음 SET 진입부터 적용됩니다. 내비가 없거나 오래된 경우, 순정 ACC 및 이미 인게이지된 상태의 버튼 동작은 기존과 같습니다.

### 차량 조향 — 상위 44개 + ONNX 상세 6개 + 검색 전용 1개

| 세부 구역 | 파라미터 | 용도 |
|---|---|---|
| ONNX 차선·BSD | `ShareData`, `OnnxBsdEnabled`, `OnnxLaneThreshold`, `OnnxLaneIntervalMs`, `OnnxBsdThreshold`, `OnnxBsdSmoothingMs`, `OnnxBsdIntervalMs` | 차선 종류 인식과 별도 카메라 BSD 실행 및 세부 조정 |

| [차로 변경](lane-change.md)·자동 턴 | `LaneChangeNeedTorque`, `LaneChangeDelay`, `LaneChangeBsd`, `LaneLineCheck`, `BlinkerLatchedTurn`, `LaneChangeLeverWait`, `AutoTurnControl`, `AutoTurnControlSpeedTurn`, `AutoTurnControlTurnEnd`, `AutoTurnMapChange` | 차로 변경 진입 조건과 ATC 동작 |

| 고급 토크·토크 계수 | `ChevroletSteerFF`, `LateralTorqueCustom`, `LateralTorqueAccelFactor`, `LateralTorqueFriction`, `LateralTorqueKpV`, `LateralTorqueKiV`, `LateralTorqueKf`, `LateralTorqueKd`, `LatTorqueLimitPFilter` | 커스텀 토크 제어 계수 |
| 고급 토크·검색 전용 | `NNFF` | 토크 조향의 신경망 피드포워드 옵션 |
| 고급 토크·조향 제한 | `CustomSteerMax`, `CustomSteerDeltaUp`, `CustomSteerDeltaDown`, `CustomSteerDeltaUpLC`, `CustomSteerDeltaDownLC` | 최대 조향 토크와 토크 변화율 제한 |

`ONNX 차선·BSD 인식`(`ShareData`)은 장치에서 차선 종류를 계산하는 설정입니다. 시각 BSD는 상세 화면의 별도 `OnnxBsdEnabled` 설정으로 켜야 하며 기본값은 꺼짐입니다. 켜면 모델이 추정한 차로 폭이 2m 이상인 설정된 좌우 영역을 번갈아 검사하고 속도나 차로 변경 방향은 실행 조건으로 사용하지 않습니다. BSD 모델은 사각지대 위협, 근접 차량 없음, 멀거나 뒤쪽에 있는 차량을 구분합니다. `OnnxBsdEnabled`가 꺼지면 BSD ONNX 네트워크를 언로드하지만 차선 인식은 계속됩니다. 차선 인식과 스냅샷을 위해 비전 서비스와 카메라 구독은 유지되며 차량 자체 BSD에는 영향이 없습니다. 상세 화면은 기능 토글을 맨 위에 유지하고, 바로 아래의 분리된 카드에 BSD 감지영역 편집기를 표시합니다. 좌우 선택, 영상 갱신, 점 되돌리기, 점 초기화와 영역 저장만 기본 화면에 두며, 영상 왼쪽 위의 사각형 점 목록은 `1(좌)`, `1(우)` 형식으로 표시됩니다. 선택된 점이 없을 때 빈 화면을 누르면 별도 모드 없이 점이 추가되고, 확대·화면 이동·영역 전체 이동 없이 선택된 점만 이동합니다. 4개 편집 버튼 바로 아래의 좌우 2열 버튼으로 도로·와이드 카메라 영상을 팝업에서 확인합니다. 실행 상태·좌우 신뢰도·처리 성능과 6개 상세 설정은 우측 아래의 **고급 설정 펼치기/접기** 텍스트로 봅니다. 편집기는 마지막 카메라 영상 한 장을 보관하고, 영상이 없으면 흐린 기본 주행 예시 화면을 표시합니다. 영역 저장은 현재 세션에서 실제 카메라 영상을 받은 뒤에만 가능합니다. BSD는 기본값이 꺼짐이며 저장한 설정은 서비스 재시작 후에도 유지됩니다. 필요한 OpenCV는 업데이트에 포함되어 정상 시작 시 자동 준비됩니다. ShareData가 켜져 있어도 서비스는 onroad 초기화와 모델·CAN·Panda 준비가 완료되어 주행 준비 상태가 0.5초 유지된 뒤 시작합니다. 실제 크루즈 활성화는 필요하지 않습니다. Offroad에서는 종료하고 다음 onroad에서도 다시 기다립니다. [동작 조건과 세부값](lane-change.md#sharedata--onnx-차선bsd-인식)을 참고하세요.

`UseLaneLineSpeed`로 레인모드를 사용하더라도 모델 속도 궤적의 시작값이 실제 차속의 70% 미만이거나 끝값이 시작값의 70% 미만이면 일시적으로 레인리스로 전환합니다. 속도 조건이 약 1초간 연속으로 정상이고 기존 차선·속도 조건도 충족해야 레인모드로 복귀합니다.

레인리스 주행은 모델이 낸 곡률로 조향하므로 `PathOffset`(레인모드 경로)과 `AdjustLaneOffset`(레인모드)은 레인리스에서 차 위치를 바꾸지 않습니다. 대신 **최소거리 클램프**가 차가 차선이나 도로경계에 너무 붙지 않게 막습니다. 2026-11-18에 예전의 레인리스 화면 이동 보정(`LanelessCenterOffset`·`LanelessEdgeOffset`·`LanelessLineGap`)을 없애고 이것으로 바꿨습니다. aabc88/openpilot `ej` 브랜치의 같은 기능을 옮겼습니다.

- `ClampEnable`(기본 켜짐): 차 중심이 감지된 차선에서 `ClampMinDistLane`(cm, 60~200, 기본 135)보다 가까워지지 않게 합니다. 차폭 2m면 옆면과 선 사이가 약 35cm입니다.
  - 차선은 신뢰도가 0.5를 넘으면 쓰기 시작하고 0.3 아래로 떨어져야 그만 씁니다.
  - 그쪽 차선이 안 보이면 도로경계(연석)에서 `ClampMinDistEdge`(cm, 40~180, 기본 115)를 지킵니다. 모델이 경계 위치를 확신할 때(표준편차 0.5m 미만)만 씁니다.
  - 차로가 양쪽 거리 합보다 좁으면 차로 가운데로 갑니다.
- 레인모드에서는 따라가는 경로(`PathOffset` 포함)에서 기준을 넘은 부분만, 넘은 만큼 밀어냅니다. 평소에는 경로를 건드리지 않습니다.
- 레인리스에서는 1초 앞(5~30m) 지점에서 모델이 그린 경로가 기준을 20cm 넘게 넘으면, 그 거리를 곡률로 바꾼 작은 보정을 모델 곡률에 더합니다.
  - 10cm 아래로 들어오면 끕니다.
  - 보정은 횡가속 1.5m/s²와 곡률 0.02를 넘지 않고, 0에서 최대까지 약 0.5초에 걸쳐 서서히 바뀝니다.
  - `ClampSteerGain`(×0.1, 0~20, 기본 10 = 1.0배)으로 세기를 바꿉니다. 0이면 레인리스 보정만 끄고 레인모드 경로 클램프는 그대로입니다.
- 레인모드·레인리스 모두 차선변경 중, 깜빡이를 켠 동안, 그리고 차선변경이 끝난 뒤 2초는 쉽니다. 시속 5km 아래에서는 꺼져 있고 10km까지 서서히 켜집니다.
- 차선변경·깜빡이, 기능 끄기, 저속, 모델 데이터가 무효이거나 끊긴 경우에는 레인리스 보정을 서서히가 아니라 그 즉시 0으로 끕니다. 가속해서 속도가 올라가도 보정은 그 속도의 상한(횡가속 1.5m/s²)을 넘지 않습니다.
- `ClampSteerAlert`(기본 켜짐): 레인리스 보정이 걸리면 화면에 `클램프 조향 보정 작동`이 작게 뜨고 띵 소리가 납니다. 끝난 뒤 5초 동안은 다시 울리지 않습니다. 끄면 알림만 없어지고 보정은 그대로입니다.
- 설정은 저장 후 약 1초 안에 적용됩니다. 클램프·횡저크 설정은 제어 루프(100Hz)에서 1초에 한 번만 읽고, 차선 계획 쪽은 다른 설정과 함께 초당 2번 읽습니다.
- 모델이 보는 영상은 더 이상 옮기지 않습니다. 화면의 차선·경로 그림과 모델 출력은 원래 카메라 기준 그대로입니다.

`SteerActuatorDelay`는 높을수록 더 일찍 조향하도록 보상하고, `LatSmoothSec`는 높을수록 부드러워지는 대신 반응이 늦어질 수 있습니다. 두 값을 동시에 바꾸면 원인을 구분하기 어렵습니다.

`SteerRatioRate`의 기본값 `100%`는 학습된 조향비를 그대로 적용합니다. `CustomSR=0`일 때 사용되며, 저장된 비율이 허용 범위(`30~200%`)를 벗어나면 안전하게 `100%`로 대체됩니다.

`LateralAccelLimit`(횡가속도 상한, ×0.1m/s², `30~90`, 기본 `30`)은 모델이 요청한 조향 곡률을 자르는 횡가속도 상한입니다. 기본값 `30`(3.0m/s²)은 오픈파일럿 기본 기준(ISO 11270)이며 지금까지와 같게 동작합니다.
- 쉐보레(NNFF 사용, 프로그파일럿과 같은 조향 경로)는 이 값을 모든 속도에 씁니다.
- 그 외 차종은 80km/h 아래의 4.5m/s² 완화를 그대로 두고(이 값이 4.5보다 크면 이 값), 80~120km/h에서 이 값으로 바뀝니다. 그래서 그 외 차종은 주로 고속에서 차이가 납니다.
- 노면 기울기(롤) 보정은 그대로 더해지고, 꺾는 빠르기 제한(5.0m/s³)은 바뀌지 않습니다.
- 주행 중 바꾸면 약 1초 안에 읽고, 초당 0.5m/s²씩 서서히 바뀝니다.
- 실제로 꺾이는 양은 차의 최대 조향 토크와 차종별 조향 제한을 넘지 않습니다. 트래버스처럼 토크가 먼저 한계에 닿는 차는 올려도 더 꺾이지 않을 수 있습니다. 4.5를 넘기면 대부분의 차가 최대 토크에 오래 붙고, 그때 핸들이 돌았다 풀렸다 흔들릴 수 있습니다(예: 트래버스 시속 45km 커브에서 4.4를 요구하자 최대 토크로 3.0~3.6만 나오고 핸들이 흔들림).
- 3.0보다 높이면 오픈파일럿 안전 기준보다 더 세게 꺾을 수 있습니다. 운전자가 언제든 개입할 수 있어야 합니다. 범위를 벗어나거나 읽을 수 없는 저장값은 `30`으로 처리합니다.

`LatJerkMax`(횡저크 상한, ×0.1m/s³, `20~100`, 기본 `50`)는 모델이 요청한 조향 곡률이 바뀌는 속도의 상한입니다. 기본 `50`(5.0)은 오픈파일럿 기본값과 같습니다. 높이면 커브에 들어갈 때 핸들이 더 빨리 돌지만 급해질 수 있고, 낮추면 부드럽지만 늦게 따라갑니다. `LateralAccelLimit`과는 별개이며, 저장 후 약 1초 안에 적용됩니다.

VW MEB(ID.4 포함)에도 수동 조향비와 학습 비율이 적용됩니다. `CustomSR=159`는 조향비 `15.9`를 사용하며 학습 비율보다 우선합니다. `CustomSR=0`, `SteerRatioRate=100%`로 설정하면 학습된 조향비를 그대로 사용하며, 변경은 제어 중 다시 읽어 반영합니다. 수동 조향비는 학습 자체를 중지하지 않고 제어에 사용할 값을 선택합니다.

이전에 ID.4에서 무시되던 저장값도 이제 적용됩니다. 예를 들어 `CustomSR=0`에서 저장된 비율이 `30%`이면 학습값의 `0.3배`가 사용되므로, 학습값 그대로 사용하려면 비율을 `100%`로 설정하세요.

`LateralTorqueCustom`과 `CustomSteer*` 계열은 차량의 기본 조향 튜닝과 안전 제한에 영향을 줄 수 있는 고급 항목입니다. 차종별 검증값과 복구 방법이 없으면 변경하지 마세요.

GM 차량의 `CustomSteerMax`는 300을 넘겨도 300으로 제한됩니다. 트래버스 로그에서는 명령이 약 300을 넘는 동안 EPS가 보고한 토크(`LKATorqueDelivered`)가 약 3.00에 머물렀고, 300~400 명령은 토크를 줄일 때 지연만 만들었습니다.

쉐보레 트래버스·트레일블레이저·트랙스·볼트 No-ACC(CHEVROLET_BOLT_CC)·볼트 ACC w Pedal(CHEVROLET_BOLT_ACC_PEDAL)·말리부 ASCM 하네스(CHEVROLET_MALIBU_ASCM)·말리부·말리부 CC·볼트 2019(CHEVROLET_VOLT_2019)·볼트 LT(CHEVROLET_VOLT_CC)는 LKA 토크 명령을 약 33 Hz(3프레임마다)로 보내고, 기본 변화량은 증가 10·감소 15입니다(FrogPilot과 같음). 트레일블레이저·트랙스·볼트 No-ACC는 트래버스와 같은 값으로 맞췄을 뿐 실차 검증은 하지 않았습니다. 말리부 ASCM 하네스는 트래버스와 같게 맞췄고(StarPilot의 GM 주기와도 같음), 이 브랜치에서 실차 검증은 하지 않았습니다. 말리부·말리부 CC·볼트 2019·볼트 LT는 트래버스처럼 트레일블레이저 NNFF 모델을 빌려 쓰므로 조향도 트래버스와 같게 맞췄습니다(2026-11-19 사용자 요청, 실차 검증 전). 볼트 LT는 예전에 횡제어 튜닝이 비어 있어 `NNFF`를 끄고 인게이지하면 횡제어 계산이 오류로 멈췄습니다. 이제 NNFF를 꺼도 트래버스처럼 토크 제어를 씁니다. 볼트 No-ACC는 2026-11-17 볼트 EUV No-ACC 로그(75 km/h 커브)에서 예전 값(25 Hz, 증가 5, 0에서 300까지 2.4초) 때문에 제어기는 최대 토크를 요청하는데 실제로 보낸 토크는 0.05에서 초당 0.4씩만 올라 차가 커브 바깥 차선을 넘은 것을 보고 바꿨습니다. 같은 지문을 쓰는 볼트 EV 2017-23 No-ACC와, ACC가 있는 볼트 EUV(CHEVROLET_BOLT_EUV, 예전 값 그대로)는 확인하지 않았습니다. 0에서 300까지 약 0.9초가 걸립니다. `CustomSteerDeltaUp`/`CustomSteerDeltaDown`을 0보다 크게 두면 이 값을 덮어씁니다. 트래버스에서 검증한 값은 정확히 10/15입니다. GM 차종은 사용자 값이 판다 안전 한도를 넘지 않게 잘라서 씁니다: 감소는 최대 25, 증가는 33 Hz 차종 최대 12·25 Hz 차종 최대 16입니다. 판다는 250 ms 안의 누적 변화를 128로 제한하는데, 볼트 No-ACC를 33 Hz로 바꾼 뒤 증가 15로는 이 한도를 넘는 것이 판다 안전 코드 실행으로 확인됐기 때문입니다(한 명령 분의 시간 오차 여유 포함). 제어 주기가 잠시 밀렸다가 몰아서 보내지는 경우에도 이 한도를 넘지 않도록, GM은 최근 약 0.29초 동안 보낸 명령(시작 직후에는 판다의 초기 기준 0 포함)을 기준으로 토크 증가를 한 번 더 잘라 보냅니다. 정상 주기에서는 이 단계가 토크를 바꾸지 않고, 0 쪽으로 푸는 것은 막지 않습니다. 낮은 값(예: 6/8)에서는 큰 커브에서 토크가 요청을 따라가지 못해 핸들을 감았다 풀었다 하는 현상이 로그로 확인됐습니다.

자체 NNFF 모델이 없는 쉐보레(트래버스·말리부·말리부 CC·말리부 ASCM 하네스(CHEVROLET_MALIBU_ASCM)·볼트 2019(CHEVROLET_VOLT_2019)·볼트 LT(CHEVROLET_VOLT_CC)·트레일블레이저 CC·트랙스)에서 `NNFF`를 켜면 트레일블레이저 NNFF 모델을, 볼트 No-ACC(CHEVROLET_BOLT_CC)와 볼트 ACC w Pedal(CHEVROLET_BOLT_ACC_PEDAL)에서 켜면 볼트 EUV NNFF 모델을 대신 씁니다. 쉐보레 차종이 NNFF로 달리면 FrogPilot NNFF와 같은 횡제어 계산을 씁니다: 저속 보정 표, 조향 속도 저크 입력, 학습 지연 기준 저크 시간, 토크 한계에서 적분을 깎지 않음, 마찰 보정 없음, 경사(pitch) 입력, 목표 횡가속 상한 3.0 m/s². 자체 모델이나 대체 모델이 있으므로 모든 쉐보레 차종에서 적용됩니다. 볼트 EUV(CHEVROLET_BOLT_EUV)와 볼트 2017-18(CHEVROLET_VOLT)은 콤마 자체 NN이 있지만 FrogPilot처럼 NNFF를 먼저 씁니다(볼트 EUV 모델은 FrogPilot 것). 볼트 No-ACC(CHEVROLET_BOLT_CC)도 콤마 자체 NN이 있지만 NNFF를 켜면 볼트 EUV 모델로 NNFF를 먼저 씁니다. 2026-11-17 볼트 EUV No-ACC 주행 로그 두 구간의 일정한 커브에서 실제로 들어간 토크가 콤마 자체 NN 앞먹임의 1.50~1.64배, 볼트 EUV NNFF 모델의 1.05~1.12배였기 때문입니다(오프라인 비교, 실차 효과는 확인 전). 같은 지문을 쓰는 볼트 EV 2017-23 No-ACC에는 이 모델이 맞는지 확인되지 않았습니다. 트래버스 말고 트레일블레이저 모델을 빌려 쓰는 차종(2026-11-19 사용자 요청: 말리부 ASCM 하네스에 이어 NNFF 모델이 없는 쉐보레 전부)에 이 모델이 맞는지는 실차로 확인되지 않았습니다. 볼트 2019·볼트 LT는 같은 볼트 계열인 볼트 2017-18 모델이 있지만, 요청대로 트레일블레이저 모델을 씁니다. NNFF를 끄면 이 차종들은 예전 그대로입니다. GMC 시에라 1500 2020-21도 실버라도와 같은 `CHEVROLET_SILVERADO` 지문을 쓰므로, NNFF를 쓰면 같이 적용됩니다. 그 밖의 쉐보레가 아닌 차종은 바뀌지 않습니다.

트레일블레이저(CHEVROLET_TRAILBLAZER)만은 NNFF로 달릴 때 한 가지가 다릅니다. 요구 횡가속이 1 m/s²를 넘으면 NNFF가 오차에 더 세게 반응하도록 섞는 "오차 블렌드"를 쓰는데, 이 비중을 55 km/h 이하에서는 0.3배로 줄이고 65 km/h에서 원래대로 되돌립니다. 2026-11-15 트레일블레이저 주행 로그에서 33~47 km/h 커브마다 핸들을 약 1초 주기로 풀었다 감는 현상이 있었습니다. 같은 제어기를 쓰는 트래버스에는 이 현상이 없었습니다. 이 블렌드가 저속 급커브에서 피드백을 2배 넘게 키우는 것은 계산으로 확인했고, 그것이 트레일블레이저의 저속 조향 반응과 겹쳐 진동한다고 보고 있습니다(추정). `LateralTorqueKpV`·`LateralTorqueKiV` 설정값은 그대로이고, 요구 횡가속 1 m/s² 미만(직진·완만한 커브)과 65 km/h 이상, 트레일블레이저가 아닌 차(트레일블레이저 모델을 빌려 쓰는 트래버스·트레일블레이저 CC 등 포함)의 계산식은 바뀌지 않습니다. 다만 직전 저속 커브에서 쌓인 적분값은 저절로 줄지 않고, 이후 주행 오차에 따라 바뀔 때까지 남습니다. 0.3배와 55/65 km/h는 로그로 정한 잠정값이며 실차 효과는 아직 확인 전입니다.

  - 롱컨에서는 오픈파일럿이 가속·회생(0x2CB), 마찰 브레이크(0x315, SASCM이 EBCM으로 전달), ACC 계기판 상태(0x370)를 파워트레인 버스로 보내고, 판다는 ASCM이 보내는 같은 세 메시지를 차로 넘기지 않습니다. ASCM은 그대로 살아서 레이더를 돌리므로, 오픈파일럿은 레이더 버스(버스 1)로 아무것도 보내지 않습니다.

  - 롱컨에서는 레이더의 '센서 막힘'(FLRRSnsrBlckd) 비트를 레이더 오류로 보지 않습니다(2026-11-23). 2026-11-21 친구 말리부 로그에서는 SASCM이 롱컨 모드로 바뀌어 있을 때, 살아 있는 ASCM이 레이더에 보내는 차속·조향 정보(0x308·0x306)가 주행 내내 고정값이었고, 레이더는 평소 정지 때만 쓰는 모드로 동작했습니다. 그 상태에서 한 번 이 비트가 켜져 "레이더 오류: 차량을 재가동하세요"가 뜨며 해제됐습니다. 고정된 정보가 원인으로 추정되지만 확정은 아닙니다(같은 상태로 4분을 더 달린 다른 경로에서는 켜지지 않았습니다). 비트가 켜진 뒤에도 레이더 표적은 계속 나왔고, 카메라 앞차와의 거리 차도 그 전과 비슷했습니다(카메라 거리도 추정치라 실제 정확도는 아닙니다). 다른 레이더 고장 비트(하드웨어·정렬·요레이트 등)는 그대로 오류로 처리하고, 순정 ACC로 달릴 때는 이 비트도 예전처럼 오류입니다. 롱컨에서는 카메라 앞차와의 거리 차가 순정 ACC 때보다 컸습니다(중앙값 8% 대 13~15%). 대신 레이더가 정말 가려져 표적이 사라져도 오픈파일럿이 스스로 해제되지 않습니다. 그때 앞차는 카메라로만 잡으므로, 레이더 쪽이 더러워졌을 때는 특히 주의해야 합니다.
  - ASCM이 0x370에 싣는 순정 충돌 경고(FCWAlert)는 판다가 ASCM의 0x370을 막는 대신, 오픈파일럿이 보내는 0x370에 그대로 옮겨 실어 차로 보냅니다(StarPilot과 같음). 오픈파일럿 화면·소리 경고는 새로 추가하지 않았습니다.
  - 가속·회생 한계는 같은 차를 ASCM 없이 롱컨하는 `Chevrolet Malibu Premier 2017`과 같습니다(최대 1018 Nm, 회생 -650 Nm, 꺼져 있을 때 -650 Nm, 브레이크 최대 400). 판다도 같은 한계로 검사합니다. 종제어 튜닝(kp 1.0, ki 0.3)도 그 차와 같습니다.
  - 2026-11-21 친구 말리부 로그의 ASCM 원본 프레임과, 오픈파일럿이 만드는 0x2CB·0x370의 바이트 배치가 같은 것을 확인했습니다. 실제 카컨트롤러를 판다 안전 코드에 물려 가속·유지·급제동·해제를 돌렸을 때 판다가 막은 프레임은 없었습니다. 실차 검증은 아직 하지 않았습니다. 처음에는 빈 도로에서 언제든 브레이크를 밟을 준비를 하고 시험하세요.
- 브레이크 판단은 ASCM 경로와 같이 가속페달 위치 메시지(0xBE)의 브레이크 값이 10 이상일 때이고, 판다도 같은 기준을 씁니다. 0xBE가 없는 차는 StarPilot처럼 엔진 상태 메시지(0xC9)의 브레이크 스위치를 쓰고, 판다는 0xBE 대신 브레이크 페달 위치 메시지(0xF1)를 수신 검사합니다.
- 버스에 페달 메시지(0x201)가 보여도 페달 종제어로 바뀌지 않습니다. 순정 ACC일 때 판다가 이 차에서 보내게 하는 것은 조향 명령, ASCM 쪽 PSCMStatus, ASCM 쪽 취소 버튼뿐입니다.
- 조향은 트래버스와 같습니다. 약 33 Hz, 증가 10·감소 15로 보내고, `CustomSteerMax`·`CustomSteerDeltaUp`·`CustomSteerDeltaDown`도 트래버스와 같은 범위로 적용됩니다. 판다의 조향 검사도 다른 GM 차종과 같습니다(StarPilot은 판다가 조향 한도 위반을 막지만 이 브랜치의 GM은 막지 않습니다). 조향 토크 기본값은 기존 말리부와 같습니다(볼트 2017-18 값을 대신 씀). `NNFF`를 켜면 트래버스처럼 트레일블레이저 NNFF 모델을 대신 쓰고, FrogPilot과 같은 NNFF 횡제어 계산도 트래버스와 같이 씁니다. 이 모델이 말리부 조향에 맞는지는 실차로 확인하지 않았습니다.
- 레이더는 버스 1에 순정 레이더 메시지가 전부 있을 때만 읽습니다.
- 콤마 화면의 속도는 트래버스처럼 계기판 숫자에 맞춰 보여 줍니다(2026-11-20, 말리부 3종 모두). 현재속도는 바퀴 속도에 1.046을 곱한 값입니다. 2026-11-19 말리부 ASCM 주행 로그에서 ECM 차속(0x3E9)이 바퀴 속도보다 15~70 km/h 전 구간에서 4.5~4.8% 높았기 때문입니다. 계기판 속도 메시지(0x260)가 있는 말리부는 예전처럼 그 값을 씁니다. 설정속도는 순정 ACC 설정속도(0x370)를 같은 비율로 바꿔 보여 주며, 순정 ACC로 달리는 말리부 ASCM은 `SpeedFromPCM` 값과 관계없이 항상 순정 설정속도를 표시합니다. 이 차의 판다는 순정 크루즈에 취소 버튼만 보내게 허용하므로, 당근이 따로 잡은 설정속도로 순정 값을 바꿀 수 없기 때문입니다. 오픈파일럿 종제어를 쓰는 말리부는 계기판 숫자로 잡은 설정속도를 같은 비율로 실제 목표 속도로 되돌리고(트레일블레이저·트랙스와 같은 방식), 계기판으로 보내는 설정속도도 같은 비율로 맞춥니다. 속도·가감속 계산에 쓰는 바퀴 속도는 바뀌지 않습니다. 계기판이 설정속도를 현재속도와 같은 비율로 보여 준다는 것은 트래버스에서 잰 결과를 따른 것이며, 말리부 계기판과 실제로 맞춰 보지는 않았습니다.
- `Chevrolet Malibu Premier 2017`(ASCM을 빼고 콤마가 대신하는 방식)과 `Chevrolet Malibu No ACC`는 바뀌지 않았습니다. ASCM을 살린 차에서 이 둘을 고르면 판다가 ASCM을 차에서 끊거나 순정 ACC를 쓸 수 없어 CAN 오류나 인게이지 불가가 생깁니다.
- 실차 검증은 아직 하지 않았습니다(2026-11-19). 맥에서 실제 차량·판다 코드로 시험만 했습니다.

#### NNFF 토크 제어

`NNFF`는 기본값이 꺼짐인 신경망 피드포워드 옵션입니다. 켜면 조향각 제어가 아닌 차량에 토크 제어 튜닝을 사용하며, 대응 모델이 있으면 NNFF를 적용합니다. comma 자체 NNFF 지원 차종은 기존 자체 경로가 우선하고(쉐보레 볼트 EUV·볼트 2017-18은 FrogPilot처럼 NNFF가 우선, 볼트 No-ACC는 볼트 EUV 모델로 NNFF가 우선), 조향각 제어 차량에는 적용되지 않습니다.

끄면 이 NNFF 옵션을 사용하지 않으며 별도 `NNFFLite` 값은 바꾸지 않습니다. 변경은 다음 주행 시작 또는 기기 재부팅 후 적용되며, 주행 중 즉시 바뀌지 않습니다. 시작 안내 문구가 보이지 않는 것만으로 적용 여부를 판단하지 마세요.

#### 쉐보레 조향 앞먹임 선택

`ChevroletSteerFF`(고급 토크 › 토크 계수, 2026-11-21)는 쉐보레 차종(`CHEVROLET_` 지문)의 조향 토크 앞먹임을 고릅니다. 다른 브랜드에서는 메뉴에 보이지 않고, GMC·뷰익·캐딜락은 저장해도 아무것도 바뀌지 않습니다.

- `0 기본`: 지금처럼 `NNFF` 토글과 차종별 모델(위 설명의 대체 모델 포함)을 따릅니다. 기본값입니다.
- `1 트블 NNFF`: 트레일블레이저 NNFF 모델을 씁니다. 트래버스가 기본으로 쓰는 모델입니다.
- `2 볼트 NNFF`: 볼트 2017-18 NNFF 모델을 씁니다.
- `3 볼트 선형`: NNFF 없이 볼트 2017-18 토크 상수(횡가속 계수 1.596, 마찰 0.157)로 일반 토크 제어를 합니다. 업스트림과 StarPilot이 말리부에 쓰는 값입니다. 콤마 자체 NN과 볼트·실버라도용 곡선 근사도 쓰지 않습니다. NNFF가 아니므로 위의 FrogPilot NNFF 계산(학습 지연 반영, 마찰 보정 없음, 목표 횡가속 상한 3.0 등)도 쓰지 않고 일반 차량과 같은 토크 제어를 합니다. `NNFFLite`는 켜 두었으면 그대로 적용됩니다.

1·2·3은 `NNFF` 토글과 관계없이 적용되고 콤마 자체 NN보다 우선합니다. 1·2를 고르면 시작 안내에 `CHEVROLET TRAILBLAZER (selected)`나 `CHEVROLET VOLT (selected)`가 나오고 3은 안내가 없습니다. 시동을 걸어 주행을 시작할 때마다 차량 설정을 새로 만들면서 읽으므로, 주행 중에 바꾸면 그 주행에는 반영되지 않고 다음 시동부터 적용됩니다. 재부팅은 필요 없습니다. `LateralTorqueCustom`을 켜면 그 값이 횡가속 계수와 마찰을 덮어씁니다. 트레일블레이저만 쓰는 저속 오차 블렌드 조정은 어떤 모델을 골라도 트레일블레이저(CHEVROLET_TRAILBLAZER)에서 NNFF로 달릴 때 적용됩니다.

이 설정을 만든 이유: 2026-11-21 말리부 ASCM 하네스 로그(85~94 km/h)에서 차가 차선 안에서 약 10초 주기로 좌우로 흔들렸습니다. 토크가 3초 동안 0.12에서 0.25로 올라도 핸들각이 그대로 있다가, 토크를 풀자 한 번에 넘어갔습니다. 두 모델을 같은 입력으로 돌려 보면 일정하게 꺾는 힘은 10% 안쪽으로 비슷하지만, 목표와 어긋났을 때 마찰을 넘기는 힘은 트블 모델이 볼트 모델의 1/4~1/6입니다. 같은 날 트래버스 고속 구간(77~98 km/h)도 핸들이 버티는 비율이 비슷했습니다(43~60%, 말리부 46%). 어느 선택이 각 차에 나은지는 실차로 비교하지 않았습니다.

#### 토크 한도 근처 P 걸러내기

`LatTorqueLimitPFilter`(고급 토크 › 토크 계수, 2026-11-23)는 쉐보레가 NNFF로 달릴 때(FrogPilot 방식) 조향 토크가 한도에 붙은 커브에서 핸들을 돌렸다 놓았다 하는 것을 줄입니다. 단위는 0.01초이고 0이면 꺼짐(기본값), 30(0.3초)을 권하며 최대 60(0.6초)입니다. 메뉴는 GM 차량에서만 보입니다. 쉐보레 플랫폼이 NNFF로 달릴 때만 적용되며, 쉐보레 실버라도 플랫폼으로 인식되는 GMC 시에라 1500(2020~21)도 포함됩니다. NNFF가 아닌 쉐보레와 그 밖의 GMC·뷰익·캐딜락에서는 저장해도 아무것도 바뀌지 않습니다.

- 앞먹임(F)만으로 토크가 0.75 아래일 때는 아무것도 바뀌지 않습니다. 0.75~0.9 사이에서 서서히 걸러지기 시작해 0.9부터는 P가 설정한 시간 상수로 다 걸러집니다.
- 적분(I)은 예전처럼 거르지 않은 P로 계산합니다. 조향이 꺼지거나 운전자가 핸들을 잡고 있는 동안에는 거르지 않고, 걸러진 값을 비워 다시 새로 시작합니다.
- 최대를 0.6초로 둔 이유: 커브 출구에서 앞먹임이 아직 0.9 이상이면 P의 반대 방향 보정도 그만큼 늦게 들어옵니다. 시뮬레이션으로 확인한 범위가 0.3~0.6초입니다.
- 주행 중에 바꿔도 1초 안에 반영됩니다.

이 설정을 만든 이유: 토크 한도 근처에서는 앞먹임이 0.9쯤을 맡고 P가 나머지 0.1~0.15를 채웁니다. 차가 목표를 따라잡아 오차가 0을 지나면 P가 +에서 -로 뒤집히며 0.5초 만에 토크를 0.3쯤 빼고, 다시 뒤처지면 한도로 돌아갑니다. 트래버스 rlog(2026-11-20~23)에서 한도의 토크 하락 129번 중 125번이 P 때문이었고, 운전자 토크 제한은 80번 중 6번이었습니다. 횡가속 제한(`LateralAccelLimit`)을 3.0 위로 올리면 앞먹임이 한도에 더 오래 붙어 이런 일이 늘어납니다. 기기와 같은 제어 코드에 로그로 맞춘 조향 반응을 붙인 시뮬레이션(커브·회전 47곳)에서 0.3~0.6초로 걸렀더니 한도의 토크 하락이 20~32% 줄었고 목표 추종과 커브 출구는 거의 같았습니다. P를 낮추거나 앞먹임·적분을 늘리는 방법은 효과가 없었습니다. 토크 한도(3Nm) 자체가 물리적 한계라 완전히 없어지지는 않으며, 실차로는 아직 확인하지 않았습니다.

#### 운전자 개입 후 조향 복구

현대·기아·제네시스의 조향각 제어 차량에는 기존 3번의 조합 복구가 기본 적용됩니다. 모드 선택 설정은 제거되었으며 예전에 저장한 모드 값은 사용하지 않습니다. 토크 제어 차량에는 적용되지 않습니다.

- 조향 오차와 운전자 힘의 크기·변화가 수렴하면 제한적으로 복구합니다. 수렴이 불명확하면 상승을 멈추거나 완만하게 줄입니다.
- 지속된 개입 뒤 힘이 빠르게 감소하면 급해제 복구를 우선합니다. 낮은 힘 유지가 확인되면 오차가 작을수록 빠르게, 클수록 완만하게 토크 상한을 올립니다. 두 복구의 증가량을 더하지 않습니다.
- 다시 강하게 개입하면 빠르게 양보합니다. 목표 조향각과 기존 조향각 제한은 유지합니다.

힘 센서의 추세는 손 접촉 해제나 운전자의 인계 동의를 뜻하지 않습니다. 기존 `steeringPressed` 판정과 운전자 감시는 그대로이며, 기본 적용이 모든 차량에서 동일한 조향감을 보장하지는 않습니다.

`AutoNaviSpeedCtrlMode`는 `0` 미사용, `1` 과속카메라, `2` 과속카메라+방지턱, `3` 과속카메라+방지턱+이동식카메라입니다.

외부 내비 연결 중에는 감속·카운트다운·내비 속도 표시에 외부 내비만 사용합니다. 외부 내비의 안내 항목이 없어도 순정 내비는 제외하며, 연결 종료 또는 수신 시간 초과가 확인되면 순정 내비 설정을 다시 적용합니다.

`VehicleSpeedCameraControlMode=2`는 차량 수신 카메라의 실제 감속이 시작된 뒤 새로 가속페달을 밟으면 현재 이벤트를 무시하려는 의사로 판단합니다. 감속구간에서 가속으로 도달한 최고속도를 하한으로 유지하고 이벤트가 끝나면 초기화하며, 감속 전부터 계속 밟은 입력은 오버라이드를 시작하지 않습니다.

`AutoNaviSpeedDecelRate`의 기본값은 `120`(1.20m/s²)이며, 값이 낮을수록 더 먼 거리에서 감속을 시작합니다. 기존 저장값은 업데이트만으로 변경되지 않습니다. `AutoNaviSpeedSafetyFactor`는 감속 목표에 적용하는 제한속도 비율입니다. 감속이 이상하면 값부터 바꾸지 말고 이벤트 종류, 제한속도와 남은 거리가 정상 수신되는지 먼저 확인하세요.

`TrafficLightDetectMode`는 `0` 미사용, `1` 정지만 감지, `2` 정지와 출발을 모두 감지합니다. 모델 판단에 의존하므로 운전자가 항상 직접 확인해야 합니다.

아래 표의 **세부 구역 제목을 누르면** 실제 코드 기준의 계산 방식, 값의 방향과 주의사항을 설명한 페이지로 이동합니다.

| 세부 구역 | 파라미터 | 용도 |

| [추종응답성](cruise-gap.md#lead-response) | `LeadAccelResponse`, `LeadAccelResponseTF1`–`LeadAccelResponseTF4` | 모든 차간 단계의 앞차 출발·가속 추종과 접근 반응 |
| [당근 크루즈](cruise-gap.md#carrot-cruise) | `CruiseEcoControl`, `CruiseCoastingPercent`, `CarrotCruiseDecel`, `CarrotCruiseAtcDecel` | 연비 제어, 진입 기준속도를 고정하는 코스팅 여유(기본 0%: 기존 제어), 당근 크루즈 감속 특성 |

`MyDrivingMode`는 `1` 연비, `2` 안전, `3` 일반, `4` 고속 모드입니다. 고속 모드는 신호 감지를 무시하고 가속 성향을 높이므로 모드 이름만 보고 선택하지 말고 설명을 확인하세요.

모드별 앞차 반응 상한은 연비 2, 안전 3이며 일반·고속은 선택값을 유지합니다. 공통값과 TF별 반응을 먼저 선택한 뒤 적용하고 낮은 값과 0은 올리지 않습니다. TF 배율은 연비 ×1.1·안전 ×1.2를 유지하며 모드 여유는 복귀 때 서서히 줄입니다. 자동전환은 정지 접근·지속 서행에서 안전을 선택합니다. 정지 접근이 아니며 앞차 가속도가 1.0m/s² 초과로 약 0.5초 유지되면 일반/연비로 복귀하고, 그 외에는 흐름 회복 3초 또는 앞차 없이 15km/h 이상 주행 4초를 확인합니다.

`CruiseGapLevels`(갭 단계 수)는 버튼 순환을 2단계부터 차량 최대 단계까지 줄일 수 있으며 기본값은 차량 최대 단계입니다. 2는 TF1·TF2, 3은 TF1~TF3을 사용합니다. 다음 갭 버튼 조작부터 적용하며 사용하지 않는 TF·추종응답성 값은 보관합니다. openpilot 가감속 제어에 적용합니다.

`TFollowGap1`~`TFollowGap4`는 저장값에 `0.01초`를 곱한 시간 간격입니다. 값을 줄이면 선행차와 가까워집니다. 앞차 가속 추종은 `LeadAccelResponse`로 조절합니다. 1~3은 완만한 반응, 4는 빠른 추종, 5는 최대 추종이며 감속 시작 거리를 별도로 기억해 차간을 늘리지는 않습니다.

`LeadAccelResponse`: 앞차가 출발하거나 속도를 높일 때 따라가는 반응을 조절합니다. 낮을수록 차간을 천천히 좁히고, 높을수록 빠르게 따라갑니다. 0은 가속 반응 강화를 끄고, 5는 가장 적극적으로 따라가는 시험 단계입니다. 자세한 동작은 [추종응답성 설명](cruise-gap.md#lead-response)을 확인하세요. 추가 여유의 유지 조건은 TF 거리(속도×TF＋정지거리)의 1.2배까지 적용하고, 1.2~1.5배에서 점차 해제합니다. 1.5배 이상에서는 앞차 속도와 관계없이 여유를 회수합니다.

`SpeedTFFactor`는 선택한 기본 TF에 속도별 선형 배율을 적용합니다. 10은 변화 없음, 20은 100km/h에서 2배입니다. 단계별 `LeadAccelResponseTF1`~`TF4`는 -1이면 공통값, 0~5이면 해당 반응을 사용합니다. 반응 4~5도 속도 배율을 유지합니다. 주행 화면의 거리 바는 동적 보정이 반영된 추종 목표거리를 m로 표시합니다.


감속 미리보기는 반응 단계와 별도로 동작합니다. 상대 가속도가 줄거나 앞차가 레이더·비전 사이에서 전환되거나 사라져도, 제어 중에는 남은 보정을 점진적으로 해제합니다. 가속·브레이크 페달 개입이나 종방향 제어 종료 시에는 초기화합니다.

`LongTuning*`, `LongActuatorDelay`는 openpilot이 가감속을 제어하는 차량에서 직접적인 영향을 줄 수 있는 고급 항목입니다. 현대·기아·제네시스에서는 `LongTuningKpV`, `LongTuningKiV`, `LongTuningKf`가 안전값 `100/0/100`으로 고정되어 설정 화면에 나오지 않으며, 토요타·렉서스는 전용 보정기 앞의 중복 보정을 막기 위해 공통 게인을 `0/0/100`으로 고정·숨깁니다. 순정 ACC 차량에서는 관련 없는 항목도 있습니다.

`StoppingAccel`(정지시작가속도)은 기본 `-50`, 범위 `-100~-1`, 변경 단위 `1`로 조정할 수 있습니다(2026-11-20에 가장 약한 값을 -0.50에서 -0.01 m/s²로 넓힘). 약하게 둘수록 정지 단계 진입이 늦어집니다. 저장값에 0.01을 곱한 가속도를 사용하며, 제어에서도 범위를 제한합니다. 기존 정지 진입·감속 방식과 차종별 소프트홀드를 사용하고 변경은 약 1초 안에 반영됩니다. [정차·재출발](cruise-gap.md#stop-resume)을 참고하세요.

`VEgoStopping`(정지출발민감도)은 범위 `10~100`, 기본 `50`이며, `10`은 `0.10m/s`입니다. 기존의 `10` 미만 저장값은 자동으로 `10`으로 올리고, 주행 중에도 같은 최저값을 적용합니다.

현대·기아 CANFD 오픈파일럿 종방향 제어에서는 StopReq를 켜는 첫 프레임부터 aReqRaw·aReqValue를 0으로 보내므로, 이 설정은 StopReq 유지 중 송신 가속도를 바꾸지 않습니다. 자동 해제·재시도는 제거되었습니다.

지원되는 Tesla 차량에서 추가 차량 버스가 감지되면 장치의 **alpha longitudinal**(`AlphaLongitudinalEnabled`) 토글을 켤 때 차량 수신 제한속도에 맞춘 [크루즈 설정속도 자동 조절](tesla.md#automatic-cruise-speed)도 활성화됩니다. 내비게이션·Carrot 속도 제어가 활성 상태이면 DAS 기반 조절을 중지하고, 해당 제어가 끝난 뒤 제한속도가 다시 안정되면 재개합니다. 수동 조작에 따른 중지는 그대로 유지됩니다. 오른쪽 속도 휠을 직접 돌리면 일시 중지하며, 1초 안에 반대 방향으로 돌리거나 제어를 해제했다가 다시 켜면 재개합니다. 별도의 Carrot Web 설정은 없습니다.

  설정이 `0`이고 차량에 카메라 SCC가 적용되지 않은 상태에서, 이번 onroad의 카메라 버스(bus2, 다중 Panda에서는 해당 카메라 버스)에서 `SCC_CONTROL`(CAN-FD) 또는 `SCC12`(일반 CAN)를 수신하면 CAN 오류 화면에 **CameraSCC 설정을 켜 주세요** 안내가 표시됩니다. 수신 이력에 따른 설정 확인 안내이며 모든 CAN 오류의 원인을 확정하지는 않습니다. 설정을 자동 변경하지 않으며, 기존 제어 해제와 진입 차단은 유지됩니다. 정차 후 차량·배선에 맞는 모드를 설정하고 다음 onroad에서 확인하세요.
- `CanfdHDA2`: HDA2 차량에서만 활성화합니다.
- **계기판 CAN 직접 송신** (`HyundaiCanfdClusterDirectTx`): 현대·기아·제네시스 CAN-FD CameraSCC 차량에서 간헐적인 계기판 경고가 발생할 때 기존 직접 송신 방식과 비교하는 설정입니다. 모든 차량에서 기본 꺼짐이며 증상 차량에서 직접 켭니다. 변경 후 기기를 재부팅해야 적용됩니다. 이 설정을 지원하는 Panda 펌웨어가 필요하며, 경고 원인 해결이 검증된 것은 아닙니다.
- `EnableRadarTracks`: `-2`는 비전 전용 시험, `-1`은 비전 매칭 없이 SCC를 항상 사용, `0`도 SCC를 항상 사용, `1`은 SCC 없이 프런트 레이더-비전 매칭, `2`는 프런트 레이더와 저속 SCC-비전 매칭, `3`은 프런트 레이더-비전 매칭 실패 시 SCC 강제 사용입니다. 매칭 모드는 실패 시 확률 `0.40` 이상인 중앙 비전을 사용하고, `-1`·`0`·`3`은 SCC가 없을 때만 비전으로 전환합니다. 모든 SCC 매칭은 횡좌표를 사용하지 않습니다. SCC 전용 `-1`·`0`의 비전 폴백에는 별도 dPath 제한이 없습니다. 레거시 Mando 레이더의 32·64슬롯 차이는 자동 처리합니다. 새 정지 전방 리드는 비전 또는 동일 물체의 코너 검출로 확인해야 하며, 전방 레이더의 연속 관측만으로 승인하지 않습니다. 비전의 위치·속도와 일치하는 이동 레이더가 별도로 확인되면, 그 비전을 다른 정지 반사체의 승인·유지 근거로 사용하지 않습니다. 코너 근거도 선택한 정지 객체와 실제로 일치해야 인정합니다. 동일 객체의 코너 확인이 없는 미확정 프런트는 비전 근거가 허용된 짧은 공백을 넘겨 끊기면 객체와 확인 시간을 함께 초기화하고 다시 확인합니다. 이미 선택한 이동 프런트는 같은 실측 객체의 연속성이 유지되면 제한된 비전 거리 불확실도 안에서 L1을 유지하며, 고정 8m 차이만으로 버리지 않습니다. 더 가까운 새 매칭은 즉시 선택할 수 있고, 공백이나 물리적 급변이 생기면 이 유지 허용치를 초기화합니다. 먼 정지차는 실측 프런트의 연속 이력과 반복된 비전 위치 일치가 있을 때 완만한 곡선에서도 확인할 수 있습니다. 같은 코너의 연속된 위치·속도 근거를 함께 판단하고, 확인된 정지 프런트는 거리·시간 상한 안에서 비전 거리 흔들림을 견딥니다. 제어 거리·속도는 레이더 값을 사용합니다.

`RadarTrackFlip`은 `0: 정상`(기본값), `1: 좌우 반전`입니다. 전방 레이더 트랙의 좌우 위치·횡속도를 함께 반전하여 선행차 선택과 표시에 적용하며 SCC·코너·비전은 그대로 유지합니다. 차종별 자동 반전은 없고, 실제 좌우 불일치가 확인된 차량에서만 사용합니다. 변경 후 재시동 또는 재부팅하면 다음 OnRoad 시작부터 적용됩니다. [레이더 좌우 반전](radar.md#radar-track-flip)을 참고하세요.

Bosch MRRevo14F 수신을 지원하는 버전에서 Bosch MRRevo14F 후보 차종(실차 검증은 아반떼 AD뿐)의 Bosch 메시지 그룹이 감지되고 `EnableRadarTracks=1`~`3`이면, 이미 전송 중인 트랙을 passive 방식으로 수신하며 시작 시 레이더 활성화 UDS 쓰기와 SCC ECU 통신 비활성화를 건너뜁니다. `EnableRadarTracksResult`는 갱신하지 않으므로 실제 수신·CAN 유효성·레이더 오류로 확인하세요. passive는 차량 제어 전체가 꺼진다는 뜻이 아닙니다. [Bosch passive 수신 예외](radar.md#bosch-passive-reception)를 참고하세요.

`EnableRadarTracks=1`~`3`에서는 확인된 프런트 선행차의 바깥쪽 레이더 움직임과 비전의 먼 차량 전환이 일치하면 ACC의 미래 추종 거리 요구를 제한적으로 완화합니다. [CUT-OUT 예측 처리](radar.md)를 참고하세요.
- `CarrotRadarMode`: 전방·코너 레이더로 차량의 움직임을 계속 추적해 끼어드는 차량을 감지하고, 카메라 영상과 레이더 정보를 새로운 방식으로 맞춰 앞차를 선택합니다. 코너 레이더와 레이더 트랙 기능이 모두 없는 차량에서는 기존 방식과 동일하게 동작합니다. 가감속 동작이 달라질 수 있으므로 검증을 마친 동일 차량에서만 켭니다. 변경값은 다음 OnRoad가 시작될 때 고정되므로, 변경 후 현재 주행을 끝내고 차량을 재시동하거나 기기를 재부팅해야 적용됩니다. 기존 `RadarMotionMode` 값은 업데이트 후 처음 시작할 때 새 이름으로 한 번 자동 이관됩니다.
- `CarrotRadarCutInSensitivity`: 당근레이더모드 전용 CUT-IN 감도입니다. `0`은 사용 안 함, `1`은 둔감, `3`은 보통(기본값), `5`는 아주 민감이며 `2`와 `4`는 중간 단계입니다. 단계 `1`~`5`는 실제 측정 움직임이 각각 `0.50`, `0.40`, `0.35`, `0.25`, `0.20초` 계속될 때 확정하며, 물리 미래 예측시간은 5.0초로 고정합니다. 전방 레이더의 최근 실측 이력에서 0.50m 이상 강한 단방향 진입이 확인되면 timestamp 양자화로 확정을 놓치지 않도록 최대 20Hz 레이더 한 프레임만 반영하며, 작은 인접 차로 흔들림에는 적용하지 않습니다. 기존 레이더모드와 `EnableCornerRadar`에는 영향을 주지 않습니다. 다음 OnRoad 시작 때 읽으므로 변경 후 차량을 재시동하거나 기기를 재부팅해야 적용됩니다.
`DriverMonitoringEnabled`의 기본값은 켜짐이며 Carrot Web 설정 검색에서만 찾을 수 있습니다. 파라미터 이름으로 검색하세요. 끄기 기능은 DM 카메라가 없거나 고장 난 경우를 위한 것으로, 기본 켜짐을 변경하지 않는 것을 권장합니다. 끄면 일반 주행 중 운전자 감시 경고·감시로 인한 강제 감속·재사용 제한이 사라지며, 사용 지역과 조건에 따라 적용 법규나 운행 요건에 위배될 수 있습니다. Driver View에서는 얼굴 미리보기만 유지하고 판정은 중립입니다. Web에서 끈 설정은 다음 주행과 재시작 후에도 유지되므로 직접 다시 켜야 합니다. 파일·QR 백업, 복원 및 설정 프로필은 이 값을 제외합니다. 복원 작업은 현재 값을 바꾸지 않으며 다른 기기의 끄기 값을 가져오지 않습니다.

기어와 속도에 관계없이 정차 중에도 실제 차량 CANCEL 버튼을 놓았다 다시 누르는 방식으로 3초 안에 세 번 누르면 `DriverMonitoringEnabled` 설정을 바꾸지 않고 현재 시동 구간 동안 감시를 끕니다. 기어 또는 속도가 바뀌어도 횟수를 초기화하지 않습니다. 자동 제어 CANCEL 반사와 BT CANCEL은 세지 않습니다. 다른 차량 버튼의 누름 또는 놓음 신호, 무효·오래된 차량 상태, 입력 스트림 끊김이나 시간 초과는 횟수를 초기화하며, 실제 입력과 구분할 수 없는 순정 ACC 속도 버튼 반사도 보수적으로 초기화할 수 있습니다. 다음 시동을 켜거나 manager/기기를 재시작하면 임시 꺼짐 상태만 해제하므로, 저장된 설정이 켜짐일 때만 감시가 다시 켜집니다. `DriverMonitoringMode`와 `CarrotVisionEnabled`는 바꾸지 않습니다.

- `DriverMonitoringMode`: 운전자 감시가 켜져 있을 때 적용됩니다. 기본값 0은 카메라 사용 시 콤마 순정 감시 기준이며, 카메라 미장착·고장 시에는 15·30·45초 조작 감시로 전환합니다. 1은 빈 도로 시간 완화와 조작 후 카메라 경고 유예를 적용하는 시험 전용 실험 모드입니다. 공통 예외로 P단·완전 정차·인게이지 해제가 유효한 신호로 1초간 확인되면 재사용 제한을 초기화합니다. 모드 변경은 재부팅 없이 약 0.5초 주기로 적용됩니다. 전환해도 누적 감시시간·경고 횟수·재사용 제한은 초기화되지 않으며, 이전 조작 유예와 전방주시 연속 판정은 종료됩니다. [운전자 감시와 실험 모드 조건](driver-monitoring.md)을 확인하세요. 현대·기아·제네시스 CAN-FD의 검증된 원본 `STEER_TOUCH_2AF` 수신 신호를 차종명 제한 없이 처리하며 카메라·모드에 따라 유지와 새 접촉을 구분합니다.
- **GM 계기판 핸들 경고 (실험)** (`GmClusterTakeSteering`): 트래버스 SDGM 카메라 하네스에서 오픈파일럿 롱컨을 쓸 때만 동작하는 실험 기능입니다. 다른 차종이나 순정 롱컨에서는 저장해도 아무것도 바꾸지 않습니다. 기본값 `0`은 끔입니다. 오픈파일럿은 평소 순정 카메라에 손이 핸들에 있다고 알려 순정 'Take Steering' 경고를 숨깁니다. `1`은 경고음이 나는 운전자 감시 경고(2단계 이상)부터, `2`는 첫 감시 경고(1단계)부터, 경고가 떠 있는 동안만 손을 뗐다고 알려 순정 카메라의 계기판 핸들 경고 표시를 유도합니다. 조향 명령, 운전자 감시 판단과 실제 핸들 토크 신호는 바뀌지 않습니다. 제조사 매뉴얼에 따르면 Take Steering 경고가 반복되면 순정 차선유지(LKA)가 잠시 사용할 수 없게 될 수 있습니다. 순정 카메라의 반응 시간, 경고음, 순정 차선유지 설정 필요 여부, 다른 계기판 메시지와 반복 경고 뒤 복구는 실차에서 확인되지 않았습니다. 약 0.5초 안에 재부팅 없이 적용됩니다.
- `CarrotVisionEnabled`: 운전자 감시와 별도로 웹 도로 영상을 켭니다. `DisableDM`은 이관 전용이며, 기존 `DisableDM=2`의 영상 기능만 최초 전환 시 `CarrotVisionEnabled`로 승계합니다.
- `SpeedFromPCM`: 기본값은 `2`(커브·카메라 감속)이며, PCM 차량의 버튼 스패밍과 속도 선택에 영향을 줍니다. `3`에서 토요타·렉서스는 순정 설정속도를 사용하며 가감속 제어 방식은 바뀌지 않습니다. `TOYOTA_RAV4_TSS2_2022`의 PCM 직접 가감속에서는 `0`도 유효한 순정 설정속도 변경·크루즈 재개를 반영하며 낮은 감속 목표를 유지합니다. [버튼 전송 상세](buttons-presets.md#button-spam)를 참고하세요.
- `AutoStopOff`: 기본값은 `0`(사용 안 함)입니다. `1`이면 시동마다 엔진 오토스톱을 자동으로 끕니다. 트래버스에서 오픈파일럿 롱컨을 쓸 때만 동작하는 시험 기능입니다.
  - 시동 5초 뒤, 정차 중이고 크루즈와 오픈파일럿이 꺼져 있을 때 오토스톱 끄기 버튼 누름(`0x1E1`)을 대신 보냅니다. 그다음 오토스톱 꺼짐 상태(`0x1F4`)가 1이 됐는지 확인합니다.
  - 운전대 버튼을 누르고 있거나, 차가 움직이거나, CAN 상태가 나쁘거나, 다른 버튼 신호를 막 보냈으면 누르지 않고 진행 중이던 시도도 멈춥니다.
  - 이미 꺼져 있으면 누르지 않습니다. 주행마다 최대 3번만 시도하고, 성공하면 그 주행 동안 다시 누르지 않습니다. 운전자가 직접 다시 켠 오토스톱도 건드리지 않습니다.
  - 실제 버튼 신호 사이에 끼워 넣는 방식이라, 차에서 실제로 꺼지는지와 경고가 뜨는지는 아직 검증하지 않았습니다. 켜고 끄는 변경은 약 0.1초 안에 반영됩니다.
- `BoltPedalLongMode`: 기본값은 `1`입니다. 차종이 `ACC w Pedal`이고 콤마 페달이 있을 때만 쓰이고, 다른 차종에서는 아무것도 바꾸지 않습니다. `1`은 혼합 방식(차의 순정 ACC 명령과 당근 종제어로 가감속, 페달은 정지 후 출발할 때만), `2`는 StarPilot 방식(가속은 전부 페달, 감속은 회생 패들 신호·마찰 브레이크, StarPilot 종제어기, 원페달 필요, SET/RES로만 켜짐)입니다. 차량 설정을 시작할 때 읽으므로 바꾼 뒤 재부팅해야 적용됩니다. 자세한 내용은 위 '차량 조향' 절의 `ACC w Pedal` 단락을 보세요.

`HardwareC3xLite`는 일반 C3/C3X에서는 반드시 꺼 두고 C3X Lite에서만 켠 뒤 기기를 재부팅하세요. 이 설정을 켜면 존재하지 않는 앰프를 초기화하지 않아 I2C 재시도로 인한 시작 지연을 없애고, 경고음을 GPIO 부저로 출력합니다. 또한 `micd`, `soundd`, `loggerd`를 실행하지 않고 `RecordAudio`를 끄므로 이 하드웨어 모드에서는 일반 주행 로그 기록을 사용할 수 없습니다.

## 화면 표시

화면 표시에는 34개 항목이 있습니다. 외부 HUD 항목은 별도 하드웨어의 화면 구성과 출력 방식을 조정합니다.

`ClusterHud`(외부 HUD 활성화)는 **본체 USB에 직접 연결한 HUD 또는 등록된 ESP32-S3 Wi-Fi HUD**를 켜고 끄는 설정입니다. Jetson에 연결한 HUD는 이 값이 `0`이어도 자동 실행되며, 기본적으로 시동 OFF 시 화면을 끕니다. 시동 OFF에도 표시하려면 기존 `ClusterHudDebug`의 항상 켜기를 사용합니다. 밝기·화면 구성 설정은 Jetson HUD에도 적용됩니다.

S3 Wi-Fi 출력은 TURZX 9.2인치와 전원 공급 허브를 사용하며, C4와 S3가 같은 2.4GHz 네트워크에 연결되어야 합니다. [초기 등록 안내](../../../tools/esp32s3_display/README.md)에 따라 USB 자동 등록 또는 폰 설정 페이지의 등록 파일 가져오기를 한 번 진행하세요. 등록된 S3는 재부팅과 IP 변경 후 자동으로 다시 연결됩니다. 이 경로는 `ClusterHudEncoder` 선택과 무관하게 JPEG 품질 50·목표 15 FPS를 기본으로 사용하며, eGPU 활성 시 최대 10 FPS를 허용합니다(직접 USB는 기존 5 FPS). 실제 속도는 화면 내용과 무선 상태에 따라 달라지며, C4 차량 실측은 별도입니다. 등록 파일을 제거하고 HUD를 재시작하면 직접 USB 출력으로 돌아갑니다.

S3 N16R8 보드 선택·배선·펌웨어 설치·폰/C4 등록은 [NAS 설치 설명서](https://upload.shind0.synology.me/models/carrot-s3/index.html)에서 진행할 수 있습니다. 펌웨어 ZIP도 같은 페이지에서 제공합니다. S3 1.1.0은 소등 응답 확인과 재시도를 추가했으며, 기존 등록을 보존하여 업데이트합니다.


Jetson HUD에는 `jetSON` 아래에 Jetson 내부 센서의 최고 온도가 표시됩니다. 전체 내비게이션·그래프 화면에서는 우측 상단에 표시하며, 온도 정보가 3초 이상 갱신되지 않으면 `--°C`로 바뀝니다. 각 센서의 장치 설정 온도 한계보다 5°C 낮은 지점부터 상단에 온도 높음 경고, 한계 도달 시 과열 경고를 표시합니다. 예를 들어 성능 제한 온도가 99°C인 장치는 94°C부터 사전 경고합니다. 경고가 나타나면 팬과 통풍 상태를 확인하세요. 차량 운전 경고가 우선 표시되며, 이 온도 표시는 본체 온도·메모리 통계와 구분됩니다. 이 기능은 업데이트된 Jetson HUD 소프트웨어가 필요합니다.

`CarrotVisionEnabled`를 켜면 외부 HUD와 웹 카메라뷰를 함께 사용할 수 있습니다. 동시 영상 사용 시 기기 부하가 증가할 수 있습니다. 사용 방법은 [웹당근 안내](carrot-web.md)를 참고하세요.

`NavdyAmbientDarkOff`(불빛 없는 어두운 길에서 Navdy 앰비언트 끄기, 기본 0)를 켜면 주행 중 어둡고 주변에 가로등·도심 불빛이 없는 길에서 Navdy에 연결한 앰비언트 라이트를 끕니다. 어두움은 차의 오토라이트 조도 센서, 불빛 여부는 오토 하이빔 카메라의 판단이며 현재 쉐보레 트래버스에서만 읽습니다. 또 해가 진 뒤에만 끕니다. 태양이 지평선 아래 4°보다 내려가야 하며, 해 진 뒤 약 20분입니다(서울 기준 계산이라 지역에 따라 몇 분 차이가 납니다). 흐리거나 비가 와서 낮에 조도 센서가 어둡다고 해도 끄지 않습니다. 꺼져 있다가 새벽에 해가 지평선 아래 3° 위로 올라오면 원래 조명으로 돌아옵니다. 콤마 시계가 아직 맞춰지지 않았을 때는 이 조건 없이 아래 기준만 씁니다. 어두움이 5초, 카메라의 불빛 없음이 10초 이어지면 끄고, 도심 불빛이 15초 이어지거나 밝음이 10초 이어지면 원래 조명으로 돌아옵니다. 카메라 신호가 15초 없을 때도 원래 조명으로 돌아옵니다. 카메라는 낮에는 불빛을 판단하지 않고 늘 불빛 없음을 보내므로, 이 값은 어두워진 뒤 카메라가 불빛이나 상향등 권장을 한 번이라도 보고한 다음부터만 믿습니다. 그래서 낮 터널에서는 끄지 않고, 밤에 시동 직후처럼 카메라가 아직 판단하지 않았을 때도 끄지 않습니다. 밝음이 1분 넘게 이어지거나 시동을 끄면 이 기록을 지웁니다. 터널은 예외입니다. 전방 레이더가 터널을 감지하는 동안에는 카메라가 불빛 없음을 보내도 끄지 않고, 이미 꺼져 있었다면 터널 안에서 2초 뒤 원래 조명으로 돌아옵니다(카메라가 터널 조명을 불빛 없음으로 보는 터널이 있어서입니다). 터널을 나온 뒤 어두운 길이 이어지면 다시 10초 뒤에 끕니다. 레이더 신호가 없을 때는 위의 카메라 기준을 그대로 씁니다. P단에 넣거나 주행 중 문을 열면 바로 원래 조명으로 돌아오므로, 시동을 끈 뒤의 하차 조명과 주차 중 조명은 그대로 동작합니다. 과속 경고 깜빡임은 Navdy 앱 쪽 동작이라 꺼진 동안에도 켜질 수 있습니다. 끄는 동안 Wayon 조명 프로필을 바꾸면 새 프로필을 한 번 전달한 뒤 다시 끕니다. P단에 넣은 뒤 시동을 끌 때까지 Navdy 연결이 끊겨 있었다면 그때의 하차 조명은 생략될 수 있습니다. Wayon 앱에서 직접 켠 앰비언트 수동 조명이 있으면 그쪽이 우선합니다. Navdy 앱은 바꾸지 않고 기존 수동 조명 명령으로 끄므로 Navdy 시계가 크게 틀리면 꺼지지 않을 수 있습니다. 약 2초 안에 재부팅 없이 적용됩니다.

ARS 표시 스트림을 지원하는 RAV4 2022에서는 장치 기본 주행 화면의 `ShowRadarInfo=3`이
제어용 앞차 목록과 분리한 옆 차선 객체도 표시합니다. 1/2와 다른 수신기의 동작은 유지합니다.
표시가 제동 대상 선택이나 Toyota 코너레이더 지원을 뜻하지는 않습니다. [표시 조건](radar.md)을 참고하세요.

USB 외부 HUD 출력은 **10 FPS**로 고정되며, eGPU가 활성화되면 렌더링·인코딩·USB 출력 모두 **5 FPS**로 전환됩니다. eGPU 활성 상태가 바뀌면 자동 반영되며, H.264 인코더의 FPS 변경에는 HUD 재시작이 동반됩니다. Android 지도 입력의 `ClusterNaviMapFps`는 별도 설정입니다.

Onroad에서는 본체 UI가 CPU 6번, 외부 HUD가 CPU 7번을 일반 스케줄링의 낮은 우선순위(nice 19)로 사용합니다. Offroad에서는 4~7번 코어 절전에 대응해 0~3번으로 복귀하며, 항상 켜짐 디버그 출력도 같은 복귀 규칙을 따릅니다. FPS·CPU 코어 선택과 실시간 우선순위 설정은 제거되어 이전 저장값은 적용되지 않습니다. 부하가 높으면 실제 갱신율은 출력 제한보다 낮아질 수 있습니다.

`ShowPlotMode`는 주행 중 진단 그래프를 선택하며 `0`은 표시를 끕니다. `4`와 `5`는 모두 주 제어 대상 앞차(`radarState.leadOne`)를 사용하며, mici 본체에서도 앞차 메시지의 값이 바뀌면 그래프에 반영합니다.

| 색상 | `4`: 앞차 가속도·상대속도 | `5`: 앞차 가속도·저크 |
|---|---|---|
| 노랑 | 내 차의 계획 가속도 첫 값 `longitudinalPlan.accels[0]` (m/s²) | 내 차의 실제 가속도 `carState.aEgo` (m/s²) |
| 초록 | 앞차의 추정 가속도 `leadOne.aLeadK` (m/s²) | 앞차 가속도 `leadOne.aLead` (m/s²) |
| 주황 | 앞차와의 상대속도 `leadOne.vRel` (m/s) | 앞차 가속도 변화율 `leadOne.jLead` (m/s³) |

상대속도는 음수일 때 앞차와 가까워지고 양수일 때 멀어집니다. 앞차가 검출되지 않으면 앞차 값은 0으로 표시되며, 이 설정은 진단 표시만 바꾸고 차량 제어에는 영향을 주지 않습니다.

`ShowRouteInfo` 설명에 남아 있는 APN 표기는 경로 정보 입력 상태를 뜻합니다. 이를 CarrotMan 또는 CarrotLink 지원 안내로 해석하면 안 됩니다.

`ShowCustomBrightness=0`은 주변 밝기에 따른 자동 조절입니다. `ShowCameraWithCluster=0`은 외부 HUD 연결 중 본체 카메라를 숨기는 기존 기본 동작이고, `1`은 본체 카메라 영상을 표시합니다. `ClusterHud` 계열은 지원되는 외부 HUD를 연결한 경우에만 사용하세요.

`ShowModelView`(주행화면 구성)는 C4에서 `0` 카메라 + 차선·경로, `1` 카메라만, `2` 검은 배경에 차선·경로만, `3` 둘 다 숨김을 선택합니다. 차선·경로 그림에는 앞차 표시도 포함됩니다. 자동 밝기와 100%를 포함한 모든 밝기 설정에서 적용되며, 주행 시작 후 별도의 대기 시간은 없습니다. 주행 중 변경하면 재부팅 없이 약 5초 안에 반영됩니다. 속도·경고·운전자 상태는 계속 표시되고, 카메라 촬영·주행 판단·차량 제어는 바뀌지 않습니다. C3/C3X에는 적용되지 않습니다. 외부 HUD 연결 중 `ShowCameraWithCluster=0`이면 이 선택과 관계없이 본체의 카메라와 차선·경로를 모두 숨깁니다.

이 이식 브랜치의 Ambient HUD 밝기는 **다크 20%, 라이트 60%**입니다. 저장된 `ClusterHudBrightness`와 카메라 노출값은 무시하며 웹에서 수동값 변경도 허용하지 않습니다. `ClusterHudTheme=0`의 자동 전환은 유지됩니다. 이는 밝기 명령값이지 측정된 광량 비율이 아닙니다. `ClusterHudOrientation`은 `0`(0도)과 `2`(180도)만 지원하며 `1`, `3`은 무시합니다. TURZX 프로세스는 테마 밝기와 회전을 100ms마다 확인하며, 관리형 H.264의 회전 변경 시 HUD를 재시작합니다.

`ClusterHudPanelLayout=0`은 `ClusterHudCameraViewMode`가 선택한 주행 화면을 왼쪽에, 화면 모드·디버그·내비 상태에 따라 선택되는 정보 패널을 오른쪽에 배치합니다. `1`은 두 영역을 서로 바꿔 정보 패널을 왼쪽에, 주행 화면을 오른쪽에 표시합니다. 실행 중 약 1초 안에 적용되며 재시작하지 않습니다. 전체화면 그래프와 전체화면 내비처럼 좌우 영역이 없는 모드는 바뀌지 않습니다. `ClusterHudDebug`은 HUD 상시 출력과 디버그 UI·내비 입력을 강제로 켜는 설정이며, 그 결과 표시되는 디버그·내비 정보 패널도 선택한 좌우 배치를 따릅니다.

외부 HUD가 USB로 연결된 동안 `ShowCameraWithCluster=0`이면 일반 C3/C3X와 mici의 본체 주행 화면은 검은 배경으로 전환하고 카메라 영상과 모델 경로 렌더링을 생략합니다. `1`이면 이 연결 전용 억제를 해제해 본체 카메라 영상과 기존 주행화면 렌더 경로를 사용합니다. 값은 주행 중에도 최대 약 5초 안에 반영됩니다. 어느 값에서도 속도·제한속도·운전자 상태·경고·주행 상태 테두리 등 본체 HUD는 계속 표시되며, 외부 HUD 연결이 끊기면 이 옵션은 화면에 영향을 주지 않습니다. `0`에서도 `camerad`와 모델 입력은 계속 동작하고 본체 화면의 중복 렌더링만 줄입니다.

`ClusterHudScreenMode`의 최종 화면 구성은 다음과 같습니다.

- `-1`은 카메라 뷰 `0`, `1`의 3D 화면에서만 정보 패널과 월드 이동을 제거하고 전체 폭을 사용합니다. 왼쪽 HUD는 기존 여백을 유지하고, 오른쪽 게이지·TPMS는 물리 화면 오른쪽 여백에 맞추며, 시계·월드·방향지시등은 전체 화면 중앙축을 사용합니다. 로드카메라 뷰 `2`에서는 내비 유무에 따른 자동 주행 리포트와 `ClusterHudPanelLayout`까지 `0`과 완전히 동일하게 동작합니다.
- `0`은 기본 화면입니다. 내비가 수신되면 내비 패널을, 수신되지 않으면 주행 리포트를 자동으로 표시합니다.
- `1`은 라이브 지연·토크·조향·횡방향 계획을 2×2 카드로 묶은 일반 디버그 화면입니다. 3D 카메라 뷰에서는 모드 `0`처럼 1124px 주행 영역에 월드와 주행 HUD를 맞추고, 반대편 792px 정보 영역 전체를 네 개의 라이브 디버그 카드가 사용합니다. 가속·조향·연료·요소수 게이지와 TPMS는 주행 영역의 오른쪽 경계 안에 유지됩니다.
- `2`는 고정 시스템 디버그 화면입니다. 상세 카드에는 네트워크·출력 해상도/프레임률·카메라 상태·메모리 용량·코어별 CPU 사용률을 표시하고, 시스템 헬스 카드에는 CPU·온도·메모리·디스크 사용량을 2×2 원형 게이지로 표시하며 디바이스 피치/요 타깃과 각도 숫자도 함께 보여 줍니다. 3D 카메라 뷰에서는 모드 `0`처럼 1124px 주행 영역에 월드와 주행 HUD를 맞추고 두 카드는 반대편 792px 정보 영역을 사용합니다. 내비 연결·라이브 안내·내비 디버그 상태와 관계없이 이 화면을 유지하며, 내비·`NAVI DISCONNECTED`·경로 오버레이·주행 리포트로 자동 전환하지 않습니다.
- `3`은 주행 장면을 끄고 `ShowPlotMode` 그래프를 크게 표시합니다.
- `4`는 3D 월드와 주행 HUD를 모드 `0`과 같은 1124px 주행 영역에 맞추고, 반대편 792px 정보 영역 전체에 같은 그래프를 표시합니다. 가속·조향·연료·요소수 게이지와 TPMS는 주행 영역의 오른쪽 경계 안에 유지되며, 좌우 패널을 바꾸면 그래프와 주행 영역이 서로 함께 교환됩니다.
- `5`는 주행 리포트를 항상 표시합니다.

`ClusterHudScreenMode=5`는 정보 패널에 실시간 주행 리포트를 표시합니다. 기본 화면 모드(`0`)에서도 실시간 내비가 수신되지 않는 동안에는 이 리포트가 자동으로 표시되고, 수신이 시작되면 내비 패널로 돌아갑니다. 리포트 배경·카드·테두리·기본/보조 글자와 값이 없는 상태의 색상은 현재 `ClusterHudTheme`를 따라 자동·다크·라이트 모드에 맞게 전환됩니다. 넓은 카드에는 주행 시간·거리·평균/최고 속도·자동주행 비율·최대 가감속·급가감속/급코너 횟수를 큰 글씨로 표시합니다. 작은 카드는 CPU·온도·메모리·디스크 사용량을 2×2 원형 게이지로 표시하고, 하단 타깃은 저장된 디바이스 피치(P)와 요(Y)를 정상 중심점 대비 상하·좌우 방향으로 시각화하면서 각도 숫자도 함께 표시합니다. 주행 화면 아래에는 브랜치·네트워크 주소·프레임률 상태를 계속 표시하고, 리포트와 겹치는 코어 사용량 문구만 생략합니다. 로드카메라 화면에서는 감지 차량을 내부가 투명한 라운드 사각 프레임으로 감싸고 기존 감지 색상을 테두리에 적용합니다. 그룹화되지 않은 레이더 감지점은 같은 방식의 작은 소스 색상 표식으로 표시합니다. 차량 프레임은 가벼운 단일 테두리로 그리고, 화면 경계에서 일부만 투영되거나 레이더 방위값 때문에 비정상적으로 길어지는 프레임은 표시하지 않습니다.

외부 HUD는 기기의 `LanguageSetting`을 따라 주행 리포트, 주행 모드와 내비 상태 문구를 한글(`ko`) 또는 영어(`en`)로 실시간 전환합니다. 중국어를 포함한 그 밖의 언어값은 영문으로 표시합니다. `IsMetric`이 켜져 있으면 현재/설정/제한 속도, 내비, 레이더 라벨과 주행 리포트를 `km/h`, `m`, `km`로 표시하고, 꺼져 있으면 `mph`, `ft`, `mi`로 변환합니다. 가속도와 온도는 각각 `m/s²`, `°C`를 유지합니다. 두 설정은 약 1초마다 확인하므로 HUD를 다시 시작하지 않아도 적용됩니다.

기본 화면과 로드카메라 화면의 TPMS는 같은 위치에 표시됩니다. 기존 압력 글자 크기는 유지하며, 네 압력값을 단순한 장난감 자동차의 큰 바퀴 안에 각각 배치합니다. 네 값이 모두 없을 때만 전체가 숨겨지고, 일부 값만 없으면 해당 바퀴에 `--`를 표시하며 31 psi 미만은 빨간색으로 표시합니다.

속도 표시 옆의 주행 모드 문구는 배경과 테두리 없이 속도 숫자의 마지막 자리 위에 확대 표시합니다. 연비는 녹색, 안전은 주황색, 일반은 흰색, 고속은 빨간색입니다. 기어 배지도 내부 배경 없이 글자와 테두리만 표시합니다. 왼쪽 위의 조향/LFA·Wi-Fi·시계는 화면 가장자리 및 아이콘 사이 여백을 넓히고, 제한속도 표지는 약간 왼쪽으로 배치합니다.

`ClusterHudTheme=1`(다크)은 일반 HUD의 빈 배경을 지도와 `NAVI DISCONNECTED` 상태 영역에 사용하는 것과 같은 순수 검정으로 표시합니다. 자동(`0`)도 18:00~06:00에는 같은 다크 팔레트를 사용합니다. 도로, 게이지와 일반 정보 패널은 구분과 가독성을 위해 서로 다른 어두운 음영을 유지합니다.

CAN FD 현대·기아 하이브리드 차량에서 외부 HUD의 초록색 `EV` 표시는 ECAN에 `0xFA`와 `0x230`이 모두 DLC32로 존재할 때만 활성화됩니다. `0x230`의 4비트 하이브리드 동력 흐름 모드를 해석해 확인된 모터 주행·회생 모드 1, 2, 6에서 `EV`를 표시합니다. 일반 HUD에서만 현재 속도와 설정 속도 사이에 표시하며, 전체 내비 화면에서는 표시하지 않습니다. 그 밖의 모드이거나 지원 조건 또는 샘플이 없거나, 유효하지 않거나, 오래된 경우에도 표시하지 않습니다.

일반 외부 HUD는 현재 속도 위의 교통 상태 점 옆에 현재 주행 모드도 표시합니다. `MyDrivingMode` 값에 따라 `1` 연비는 초록색, `2` 안전은 주황색, `3` 일반은 흰색, `4` 고속은 빨간색 배지로 표시합니다. `longitudinalPlan`이 없거나 유효하지 않거나 오래되었거나 모드 값이 범위를 벗어나면 배지를 숨기며, 전체 내비 화면에서는 표시하지 않습니다. 바로 왼쪽의 빨강·초록 점은 주행 모드가 아니라 모델의 교통 상태를 나타내는 별도 표시입니다.

일반 화면과 도로 카메라 화면의 TPMS는 가속·조향·연료·요소수 게이지 아래에서 같은 고정형 차량 그림과 위치를 사용합니다. 네 압력값이 모두 없을 때만 전체 표시를 숨기며, 일부 값만 없으면 해당 위치에 `--`를 표시합니다. 31 psi 미만은 빨간색이고 차량 그림 바깥에는 별도 배경이나 외곽선을 그리지 않습니다. 외부 내비가 활성화됐거나 내비 대시보드가 연결되면 기존 우측 하단 `NAVI` 대신 Wi-Fi 아이콘 아래에 초록색 `NAV`를 표시합니다. 중앙 시계와 EV·연료·요소수 표시는 그대로 유지됩니다.

### Carrot Vision AR과 리플레이 내비 이벤트

Carrot Vision에는 `carrot_settings.json` 카탈로그와 별도로 **AR 표시**와 **AR 디버그** 설정이 있습니다. **AR 표시**를 켜면 Vision 영상 위에 주행 안내를 표시하며, 켜져 있는 동안에만 추가 실시간 데이터를 요청합니다. **AR 디버그**는 표지·앵커·렌더 수, 현재 차단 사유와 복사 가능한 변화 이력을 진단 패널에 표시합니다.

리플레이 이벤트 타임라인은 당근내비 연결과 경로 세션 변경, 현재·다음 주행 안내, 권장 차선, 도로 안전 안내, 구간단속, 신호와 교차로 안내의 변화를 구분해 표시합니다. 이 항목들은 리플레이에 기록된 상태 변화를 검토하기 위한 이벤트 라벨입니다.

## 시스템

시스템에는 녹화, 전원, 주행 모델, 네트워크, 지도, 소리와 소프트웨어 메뉴를 다루는 13개 항목이 있습니다.

| 중분류 | 파라미터 | 용도 |
|---|---|---|
| 녹화·전원 | `RecordRoadCam`, `MaxTimeOffroadMin` | 도로 카메라 저장과 시동 OFF 후 자동 전원 종료 시간 |
| 주행 모델 | `InternalModelLiveSwitch` | 컴파일된 주행 모델을 재시동 없이 디스인게이지 상태에서 바로 바꾸기(시험) |
| 네트워크·지도 | `HotspotOnBoot`, `MapboxStyle` | 부팅 시 핫스팟과 지도 배경 스타일 |
| 사운드 | `SoundLanguageSetting`, `SoundVolumeAdjust`, `SoundVolumeAdjustEngage` | 안내음 언어와 일반·인게이지 볼륨 |
| 소프트웨어 | `SoftwareMenu` | Carrot Web의 소프트웨어 메뉴 활성화 |

- `RecordRoadCam`: `0` 녹화 안 함, `1` 일반 카메라, `2` 일반+광각 카메라입니다. 저장 공간 사용량을 확인하세요.
- `MaxTimeOffroadMin`: 시동 OFF 후 종료 시간으로 최대 `4320`분(3일)을 지원하며 기존 저장값은 자동 변경하지 않습니다. 자동 종료는 차량 하네스가 연결된 것으로 판정될 때만 합니다. 하네스 미연결로 판정되는 폰 충전기·노트북 같은 USB 전원에서는 자동 종료하지 않습니다(USB 연결인데 하네스가 연결로 잘못 판정되면 예외). 시동 ON 중에는 자동 종료하지 않습니다. 시간 종료는 오프로드가 된 뒤 설정 시간과 5분 중 긴 쪽이 지나고, 시동 ON으로 운행 화면에 들어간 적이 있거나 부팅 후 1시간이 지났을 때만 요청합니다(설정이 0이어도 설치·전원 연결 직후 바로 꺼지지 않음, 2026-11-16). 저전압 종료에는 이 대기가 없습니다. 저전압 종료는 원시·필터링 전압이 모두 `11.0V` 미만으로 10초 연속 확인되면 요청합니다(2026-11-16 `11.3V`에서 변경). 시동 ON·전압 회복·측정 중단 시 저전압 확인 시간을 초기화합니다. 실제 종료 명령 직전에도 최신 시동·오프로드·하네스 상태를 재확인하며 오래된 자동 요청은 종료를 유발하지 않습니다. 추정 배터리 잔량 종료 조건은 사용하지 않으며 수동 종료·재부팅 동작은 그대로입니다. 긴 유지 시간과 낮은 전압 기준은 배터리 방전·시동 불가 위험을 높입니다.
- `InternalModelLiveSwitch`(주행 중 주행 모델 즉시 전환, 시험, `0/1`, 기본 `0`): 켜면 도구 → 주행 모델 카드에서 주행 중에도 모델을 고를 수 있고, 이미 컴파일된 모델과 기본 모델은 재시동·재부팅 없이 디스인게이지 상태에서 바로 바뀝니다. 바꾸는 동안과 새 모델의 과거 기록이 찰 때까지(약 6~8초) 인게이지가 막히고('주행 모델 바꾸는 중'), 조향·가감속 제어(`AlwaysLateral` 포함)와 정차 후 순정 크루즈 재출발 신호도 모두 멈춥니다. 젯슨·eGPU 모델로 달리는 시동에서는 다음 시동부터 바뀝니다. 끄면(기본) 예전처럼 주차하고 시동을 끈 상태에서만 고를 수 있고 다음 주행부터 바뀝니다. 전환을 기다리는 중에 끄면 전환을 취소하고 다음 시동에 적용하지만, 이미 새 모델을 불러오기 시작했으면 새 모델 기록이 찰 때까지 차단은 그대로 이어집니다. 실차 주행으로는 아직 확인하지 않은 시험 기능이니 주차(P) 상태에서 먼저 확인하세요. 자세한 동작은 [Carrot Web 주행 모델](carrot-web.md)을 참고하세요.
- `HotspotOnBoot`: USIM을 장착한 장치에서 자동 핫스팟을 사용할 때의 설정입니다.
- `SoftwareMenu`: 메모리 문제가 있을 때 끌 수 있는 Carrot Web 메뉴 설정입니다.

`SoundVolumeAdjust`는 `-1`이면 **자동**으로 표시되며 마이크로 측정한 주변 소음에 따라 일반 안내음의 음량을 조절합니다. `0`은 일반 안내음 끄기, `1~200`은 자동 음량에 곱하는 비율(%)입니다. 기존 `100`과 `-1`의 음량 곡선은 같으며 양수 설정도 고정 절대 음량은 아닙니다. 변경은 안내음이 재생되지 않을 때 다음 소음 측정부터 반영됩니다. 재부팅음은 소음 측정이 없으므로 자동 모드에서 기본 게인 `0.5`를 사용합니다. 인게이지 음량과 웹 브라우저 재생 음량은 별도 설정을 유지합니다. DM 첫 경고음은 출력 음량 최소 70%, 마지막 경고음은 항상 100%이며 볼륨 설정이나 주변 소음에 의해 낮아지지 않습니다. 그보다 앞선 화면 예고는 무음입니다. 자세한 내용은 [운전자 모니터링](driver-monitoring.md)을 참고하세요.

실험 DM은 주변 이동 차량이 없다가 처음 나타날 때만 20초간 기본 감시로 전환하고, 차량 추가로 시간을 연장하지 않습니다. 이후 실험 감시로 복귀하되 차량이 남아 있으면 빈 도로 추가 완화는 적용하지 않습니다.

## 위험도별로 접근하기

### 비교적 쉽게 되돌릴 수 있는 설정

- 즐겨찾기와 프로필

- 버튼 모드와 자동 턴
- 커브·카메라·신호 감속
- 차간거리, 정지와 가감속 튜닝
- 조향 지연, 평활화와 토크 계수

- `EnableRadarTracks`, `RadarTrackFlip`, `EnableCornerRadar`, `CarrotRadarMode`, `CarrotRadarCutInSensitivity`

- `LateralTorqueCustom`, `CustomSteer*`
- `DriverMonitoringMode`

## 신호보조 모드 (시험)

`SignalAssistMode`의 기본값은 `0`입니다. `0`은 신호보조를 끄고, `1`은 판정·표시·알림과 정차 중 적색 출발 제한을 사용하며, `2`는 여기에 주행 중 감속 준비를 추가합니다.

모드 `2`는 앞차·페달 조작·회전이 없고 속도가 5km/h 초과, 82km/h 미만일 때 유효한 적색을 확인하면 약 −0.5m/s²를 향해 점진적으로 감속을 요청합니다. 야간에는 두 개 이상의 적색 램프가 같은 방향에 지속해서 보이고 도로 범위의 지지를 얻어야 하며, 신호등 외곽 크기를 정지거리로 사용하지 않습니다.

적색 증거가 없어지거나 녹색과 충돌하면 감속 준비를 해제합니다. 정지선까지의 제어는 기존 주행 모델이 담당하므로, 이 시험 기능이 모든 적색 신호의 감속·정지를 보장하지는 않습니다.

## 안전한 변경 순서

1. Carrot Web에서 현재 값을 확인합니다.
2. 기준 프로필과 파일 백업을 모두 만듭니다.
3. 변경할 파라미터 이름, 이전 값과 변경 이유를 기록합니다.
4. 한 번에 한 항목만 `unit` 한 단계만큼 바꿉니다.
5. 재부팅 안내가 나오면 차량이 꺼진 오프로드 상태에서 재부팅합니다.
6. 허용된 시험 환경의 같은 조건에서 결과를 반복 확인합니다.
7. 나빠지거나 판단하기 어렵다면 즉시 이전 값 또는 기준 프로필로 복원합니다.

조향과 가감속의 실제 조정 순서는 [튜닝 입문](https://github.com/ajouatom/openpilot/wiki/Guide-Tuning)을 참고하세요.
