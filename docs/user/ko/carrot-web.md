# Carrot Web 사용 설명서

[English](../en/carrot-web.md)

Carrot Web은 carrotpilot 장치와 같은 네트워크에 연결된 휴대폰·태블릿·PC에서 주행 상태를 확인하고 설정, 로그, 업데이트와 진단 기능을 사용하는 로컬 웹 화면입니다.

> [!WARNING]
> 운전 중에는 Carrot Web을 조작하지 마세요. 설정 변경, 로그 선택, 터미널 명령과 도구 실행은 안전한 곳에 정차한 뒤 수행해야 합니다.

## 접속하기

1. 장치와 브라우저를 실행할 기기를 같은 Wi-Fi 또는 핫스팟에 연결합니다.
2. carrotpilot 장치의 IP 주소를 확인합니다.
3. 브라우저 주소창에 `http://장치-IP:7000`을 입력합니다.

예: `http://192.168.0.25:7000`

장치 화면에서 흰색 당근 아이콘을 누르면 현재 주소의 QR 코드가 크게 표시됩니다. C3에서는 왼쪽 아래 버튼, C4에서는 아래쪽 상태 아이콘 줄에서 누릅니다. 같은 네트워크의 휴대폰으로 QR 코드를 스캔하면 바로 접속할 수 있으며, 장치 IP가 바뀌면 열린 QR 코드와 주소도 자동으로 갱신됩니다. 긴 주소는 생략되지 않고 화면 폭에 맞게 글자 크기가 조절됩니다. 주소 아래에는 마지막 QR 갱신 시각이 `시:분:초` 숫자로 표시되고, 오른쪽에는 30초 자동 닫힘 카운트다운이 표시됩니다. QR 화면은 누르면 닫히고, 조작하지 않아도 카운트다운이 끝나면 자동으로 닫힙니다.

Carrot Web은 로컬 장치 관리 화면입니다. 인터넷에 직접 노출하거나 신뢰하지 않는 사람에게 주소, 원격 지원 링크 또는 터미널 접근 권한을 제공하지 마세요.

## 화면 한눈에 보기

화면이 넓으면 왼쪽 탐색 막대, 세로형 휴대폰에서는 아래쪽 탐색 막대로 표시될 수 있습니다.

| 화면 | 주 용도 |
|---|---|
| 주행 | 실시간 전방 영상, HUD와 주행 정보, 화면녹화 시작·중지, 저장 로그 리플레이 |
| 설정 | carrotpilot·장치 설정, 검색, 즐겨찾기, 프로필과 변경 이력 |
| 도구 | 차량 선택, 언어, 웹 화면 구성, Git 관리, 백업·복원과 시스템 작업 |
| 로그 | 대시캠 주행 로그, 구간 재생·분석·전송, 화면녹화 재생·다운로드 |
| 터미널 | 장치 터미널과 제한 시간 원격 지원 세션 |

장치 종류, 주행 상태, 선택한 브랜치와 브라우저 기능에 따라 일부 버튼이나 콘텐츠가 표시되지 않을 수 있습니다.

설정·도구·로그 화면은 휴대폰(브라우저)의 라이트/다크 설정을 따릅니다. 주행·터미널 화면은 늘 어두운 화면입니다. 아래쪽 탐색 막대는 화면 위에 떠 있는 둥근 막대로, 지금 화면이 굵은 글씨로 표시됩니다.

## 주행 화면

주행 화면은 실시간 영상과 주행 상태를 보는 곳입니다. 기본 구성은 전방 영상과 보조 정보 영역이며, `도구 > Web Settings`에서 화면 분할 방향, 표시 영역과 콘텐츠를 조정할 수 있습니다.

### 실시간 영상과 HUD

`CarrotVisionEnabled`를 켜면 외부 HUD를 사용하는 동안에도 웹 카메라뷰를 시작할 수 있습니다. 동시 영상 사용은 기기 부하를 높일 수 있으며, 영상이 끊기면 웹 카메라뷰를 중지해 비교하세요.

- `주행 비전 시작`을 누르면 카메라 스트림 연결을 시작합니다.
- 영상 위 HUD에는 차량 속도, 설정 속도, 제한속도, 차간거리, 선행차와 주행 경고가 표시될 수 있습니다.
- AR 표시는 `도구 > Web Settings`에서 켜거나 끕니다.
- 같은 영상 스트림을 다른 브라우저가 사용 중이면 `다른 기기에서 사용 중`이 표시될 수 있습니다. 정말 현재 브라우저로 옮길 때만 `여기서 사용`을 선택하세요.
- 장치가 주차 상태이거나 카메라·주행 데이터가 준비되지 않았으면 대기 안내가 표시됩니다.

HUD와 웹 영상은 참고 화면입니다. 차량의 실제 경고와 전방 상황을 우선 확인하세요.

주행 경로의 차간거리 바와 25 m 표시는 동적 보정이 반영된 현재 추종 목표거리입니다. 앞차의 실측거리와는 다르며, 유효한 앞차가 없으면 숨깁니다. 자세한 내용은 [차간거리 설정](cruise-gap.md#following-gap)을 참고하세요.

### AR 표시와 진단

- `도구 > Web Settings`의 **AR 표시**를 켜면 Carrot Vision 영상 위에 당근내비 주행 안내를 표시하고, 켜진 동안에만 카메라 자세·위치 등 추가 실시간 데이터를 요청합니다.
- **AR 디버그**는 표지·앵커·렌더 수와 현재 차단 사유를 보여 주며, 진단 이력을 복사하거나 파일로 저장할 수 있습니다.
- 리플레이 이벤트 타임라인은 당근내비 연결, 현재·다음 회전 안내, 권장 차선, 도로 안전 안내, 구간단속, 신호와 교차로 안내의 기록된 변화를 구분합니다.

### 화면 구성

`도구 > Web Settings > 화면 구성`에서 다음을 정합니다.

- 가로 또는 세로 분할
- 분할 화면, 영역 1 전체, 영역 2 전체
- 각 영역에 표시할 전방 영상 또는 지원되는 보조 콘텐츠
- 두 영역 콘텐츠 맞바꾸기

처음 설치한 기기는 가로·세로 모두 **영역 1 전체**로 시작합니다. 영역 1은 **당근비전**, 영역 2는 **당근네비**라서 주행 화면에는 당근비전이 전체 화면으로 보입니다. 분할로 바꾸면 가로는 영역 1 70%·영역 2 30%, 세로는 50%씩 나뉩니다.

`기본값` 버튼은 가로·세로 화면 구성을 **영역 1 전체 + 영역 1 당근비전 + 영역 2 당근네비**로 되돌립니다.

사용할 수 없는 콘텐츠는 대기·복구·지원되지 않음 상태로 표시됩니다. 화면 구성을 바꾸어도 차량 제어 방식 자체는 바뀌지 않습니다.

### 화면녹화 시작과 중지

주행 화면의 `Record` 버튼은 장치의 `ScreenRecord` 상태를 켜고 끕니다.

1. `Record`를 눌러 녹화를 시작합니다.
2. 주행 탐색 버튼에 `REC` 표시가 나타나는지 확인합니다.
3. 필요한 장면을 기록한 뒤 `Record`를 다시 눌러 종료합니다.
4. `로그 > 화면녹화`에서 저장된 파일을 재생하거나 다운로드합니다.

화면녹화는 화면에 보인 현상을 설명하는 데 유용하지만, 차량 제어 분석에 필요한 원본 주행 로그를 대신하지는 않습니다. 이상 동작 분석에는 [분석용 대시캠 로그 전송](dashcam-log-sharing.md)을 사용하세요.

### 저장된 주행 리플레이

`로그 > 대시캠`에서 구간 메뉴의 `리플레이`를 선택하면 저장된 전방 영상과 당시 주행 데이터를 주행 화면에서 함께 볼 수 있습니다. 이전·다음 구간 이동, 재생 속도, HUD, 이벤트·그래프·센서·원본 로그 분석 기능은 기록에 포함된 데이터와 브라우저 지원 여부에 따라 달라집니다.

실제 주행이 시작되면 안전을 위해 저장 로그 리플레이가 종료될 수 있습니다.

## 설정 화면

설정 화면 맨 위의 큰 글자 `당근파일럿`과 `디바이스`가 두 탭입니다. 굵고 진한 쪽이 지금 탭입니다.

- 첫 화면에는 검색칸, `바꾼 설정` 카드, 즐겨찾기, 묶음(그룹) 타일이 차례로 있습니다.
  - 묶음 타일에는 항목 수와 기본값에서 바꾼 개수가 나옵니다(예: `38개 · 17개 바꿈`).
  - `바꾼 설정` 카드의 큰 숫자는 기본값과 다른 설정의 전체 개수입니다. 카드를 누르면 바꾼 것이 있는 묶음만 남고, 묶음 안에서도 바꾼 항목만 보입니다. 한 번 더 누르면 전체로 돌아옵니다. 새로고침하면 다시 전체입니다.
  - 즐겨찾기는 지금 값이 카드로 나란히 보입니다. 누르면 즐겨찾기 목록으로 갑니다.
- 묶음 안 목록은 항목 이름과 지금 값만 보여 줍니다. 기본값과 다른 값은 당근색이고, 그 아래에 `기본 160`처럼 기본값이 작게 나옵니다. 제목 끝의 `(160)`처럼 기본값과 같은 괄호 표기는 목록에서 뺐습니다.
- 켜기·끄기 항목은 목록에서 바로 스위치로 바꿉니다.
- 그 밖의 항목은 줄을 누르면 아래에서 값 창이 올라옵니다.
  - 큰 숫자 양옆의 `−`/`+`(길게 누르면 연속)로 바꾸거나, 숫자를 눌러 직접 입력합니다.
  - 숫자 아래 눈금자를 좌우로 끌어도 됩니다. 가운데 바늘이 지금 값, 작은 점이 기본값입니다. 손을 떼는 순간 저장합니다.
  - `한 번에`는 −/+ 한 번에 바뀌는 양입니다. 누를 때마다 바뀝니다.
  - 설명, 설정 키, `기본값 N으로`, `변경 기록·도움말`이 같은 창에 있습니다. 선택형 항목은 선택지가 목록으로 나옵니다.
  - 바깥을 누르거나 `Esc`로 닫습니다.
- 목록 위 `전체 / 바꾼 것`으로 기본값과 다른 항목만 볼 수 있습니다.
- 넓은 화면에서는 왼쪽에 묶음 목록, 오른쪽에 항목이 나오고, 가로 1100px 이상이면 항목이 두 줄로 나란히 놓입니다.
- 설정 항목을 길게 눌러 즐겨찾기에 추가하거나 제거할 수 있습니다.
- 프로필은 여러 설정값을 묶어 저장하고 선택적으로 다시 적용합니다.
- 항목 상세 화면(`변경 기록·도움말`)에서 인기값, 최근 변경 이력과 검증된 Wiki 상세 설명을 확인할 수 있습니다.
- 일부 위험 설정은 `주의` 표시가 붙으며 재부팅 뒤 적용될 수 있습니다.
- 메뉴의 설정 초기화는 여러 값을 기본값으로 되돌리므로 현재 설정을 먼저 백업하세요.

각 항목의 범위, 단위와 튜닝 순서는 [설정 이해하기](settings.md)를 참고하세요.

### My Traverse 키

`설정 → 디바이스 → My Traverse 키`에서 이 콤마의 My Traverse(Wayon) 기기 ID와 키를 확인할 수 있습니다. 키는 콤마가 My Traverse 클라우드에 주행 기록과 사진을 올릴 때 쓰는 값입니다.

- 처음에는 키의 앞뒤 네 글자만 보입니다.
- `키 복사`를 누르고 확인하면 전체 키를 클립보드에 복사합니다. 당근웹은 https가 아니어서 브라우저가 자동 복사를 막을 수 있습니다. 그때는 아래 칸에 키가 표시되니 길게 눌러 복사하세요. 60초가 지나거나, 다른 앱·다른 당근웹 화면으로 넘어가면 지워집니다. 키를 받아 오는 도중에 화면을 떠나면 받아 온 키는 버리고 표시하지 않습니다.
- 클립보드에 복사한 키는 그대로 남습니다. 붙여 넣은 뒤에는 다른 글을 복사해 덮어 두세요.
- 이 화면은 콤마 주소로 직접 접속했을 때만 열립니다. 같은 Wi‑Fi나 본인 Tailscale에서 `http://콤마주소:7000`으로 접속하세요. 중계 서버가 붙이는 헤더(`Forwarded`, `X-Forwarded-*`, `Via`, `X-Real-IP`)가 있는 요청은 거절하고, 다른 사이트가 당근웹을 자기 화면 안에 띄우는 것도 막습니다.
- 이 보호는 "누가 키 화면에 닿을 수 있는지"를 좁힐 뿐 주인 확인은 아닙니다. 같은 Wi‑Fi나 Tailscale에서 당근웹에 접속할 수 있는 사람은 이 화면뿐 아니라 당근웹의 터미널·도구로도 같은 파일을 읽을 수 있습니다. 콤마를 믿을 수 없는 Wi‑Fi에 붙이거나 Tailscale에서 남과 공유하지 마세요.
- 키가 있으면 콤마처럼 클라우드에 접속할 수 있습니다. 다른 사람에게 보내거나 공개된 곳에 붙여 넣지 마세요.
- 키가 없다고 나오면 이 콤마에 `/data/wayon_cloud/config.json`이 없는 것입니다. 이 파일은 git 브랜치에 포함되지 않습니다. 새 콤마는 아래처럼 이 화면에서 직접 키를 발급받습니다.

#### 이 기기 키 발급받기 (다른 콤마)

키가 없는 콤마는 이 화면에서 **그 콤마 전용 키**를 직접 발급받아 My Traverse 클라우드에 별도 기기로 등록할 수 있습니다. 다른 콤마의 기록·사진·위치와 섞이지 않습니다.

1. 새 콤마의 당근웹에서 `설정 → 디바이스 → My Traverse 키`를 엽니다. 키가 없으면 `이 기기 키 발급받기` 버튼이 보입니다.
2. 버튼을 누르고 확인 창에서 `발급`을 누릅니다. 콤마가 키를 만들고, comma 기기 키로 서명해 "이 콤마가 맞다"는 것을 클라우드에 증명한 뒤 등록합니다.
3. 등록되면 `키 복사`로 키를 복사해 그 차의 My Traverse 앱에 넣으세요. 콤마는 잠시 뒤 스스로 클라우드에 접속합니다.

- comma 서버에 등록된 콤마(기기 ID가 있는 콤마)만 발급받을 수 있습니다. 다른 기기의 ID로는 등록할 수 없습니다.

## 도구 화면

도구 화면은 실행 즉시 장치 상태나 저장소를 바꿀 수 있는 관리 기능을 모아 둔 곳입니다. 위에서부터 주행 모델, 지난 주행 평가, 업데이트, 바로 가기, 기기, 설정 백업, 되돌릴 수 없는 작업 순서입니다. 제목 아래 상태 줄을 누르면 알림(작업 기록) 창이 열립니다.

### 주행 모델 바꾸기 (내장 모델)

**도구 → 주행 모델 카드**에서 콤마 자체 GPU로 돌리는 주행 모델을 고릅니다.
기본은 `CD210`(comma 공식 모델)입니다. 목록에는 이 콤마가 돌릴 수 있는 입력·출력 규격의 모델만 들어 있습니다.
기본 모델과 같은 규격(과거 기록 24프레임 또는 32프레임)과, upstream이 2026년 9월부터 쓰는 규격(과거 기록을 모델 안에 두는 방식)입니다.

- 지금 고를 수 있는 모델
  - `CD210 = WMI V12`(기본): comma 공식 모델입니다. sunnypilot의 `WMI V12`와 가중치가 똑같습니다(upstream이 같은 가중치를 다시 내보낸 것).
  - `RDF`(추천·실험): comma가 2026년 8월에 시험한 미병합 모델입니다.
  - `WMI V11`(실험): sunnypilot의 `WMI V11`입니다. V10을 되돌린 버전이라 가중치가 `WMI V9`와 같습니다. 비전은 기본 모델과 같고 정책(경로·속도 계획)만 다릅니다. sunnypilot에서 V9와 V11의 차이는 횡방향 평활화(0.1초→0초)뿐인데, 당근에서는 이 모델에도 `LatSmoothSec` 설정값을 씁니다.
  - `CH Driving`(실험): comma가 2026년 11월 5일 브랜치에만 올린 미병합 시험 모델입니다(commaai/openpilot `875a6b7e`). 기존 모델을 다시 학습한 것이 아니라 새로 학습한 모델이고, 과거 기록(32프레임)을 모델 안에 두는 새 규격입니다. 파일은 comma가 쓰는 Hugging Face 저장소에서 받습니다.
  - `Polaris Vega`, `Polaris Vega 2`(실험): StarPilot 커뮤니티의 'Polaris Series'(MIT 라이선스)입니다. comma의 RDFv4 모델을 바탕으로 행동·차선 변경(desire) 단계를 다시 학습했습니다. 잘하는 comma 모델들에서 배우고(증류), 모두 못하는 상황은 사람이 운전한 데이터로 채웠다고 합니다. 과거 기록이 32프레임입니다. `Vega`는 11월 7일, `Vega 2`는 11월 22일에 나왔습니다. 파일은 StarPilot이 공개한 Hugging Face 저장소에서 받으며, 해시가 고정돼 있어 원본이 바뀌면 받지 않고 카드에 이유를 표시합니다.
- 바꾸는 방법: 주차하고 시동을 끈 상태에서 모델을 고르고 **적용**을 누릅니다. 기본 설정에서는 주행 중에 바꿀 수 없습니다.
- **주행 중 즉시 전환(시험, 기본 꺼짐):** 설정 → 시스템 → 주행 모델의 `주행 중 주행 모델 즉시 전환(시험)`(`InternalModelLiveSwitch`)을 켜면 주행 중에도 고를 수 있고, 이미 컴파일된 모델(그리고 기본 모델)은 **재시동이나 재부팅 없이** 바로 바뀝니다. 오픈파일럿이 디스인게이지돼 있고 조향·가감속 제어도 꺼져 있을 때 바뀌며, 인게이지 중에 골랐다면 디스인게이지되는 순간 바뀝니다. 아직 시험 기능이라 주차(P) 상태에서 먼저 확인하세요.
  - 먼저 인게이지를 막고, 그 차단이 실제로 걸린 것을 확인한 다음에 모델을 불러옵니다. 그사이 인게이지하면 전환을 미루고, 다시 디스인게이지되면 바꿉니다.
  - 바꾸는 순간 모델을 불러오느라 주행 화면의 경로가 잠깐(1~몇 초) 멈춥니다.
  - 새 모델은 과거 기록이 빈 채로 시작하므로, 새 모델이 기록 길이만큼 실제로 계산할 때까지(24프레임 모델 약 5초, 32프레임 모델 약 6.5초, 그 뒤 1초 여유, 프레임이 빠지면 더 길어짐) 인게이지를 막습니다. 그동안 인게이지하려 하면 '주행 모델 바꾸는 중'이 뜨고, 조향·가감속 제어(‘항상 조향(AlwaysLateral)’ 포함)도 모두 쉽니다.
  - 젯슨이나 eGPU 모델이 주행을 맡고 있는 시동에서는 바로 바꾸지 않고 다음 시동부터 적용합니다.
  - 바꾸는 도중 modeld가 다시 시작돼도, 새로 불러온 모델의 기록이 찰 때까지 차단은 이어집니다.
  - 전환을 기다리는 중에 설정을 끄면 전환을 취소하고 다음 시동에 적용합니다. 이미 불러오기 시작했으면 기록이 찰 때까지 차단이 이어집니다.
  - 아직 컴파일하지 않은 모델은 주행 중에 컴파일하지 않습니다(주행 모델 계산과 GPU를 나눠 써야 해서 위험합니다). 주차하면 내려받기와 컴파일을 하고 다음 주행부터 씁니다. 한 번 컴파일해 두면 그 뒤로는 바로 바꿀 수 있습니다.
- 적용하면 주차 중에 콤마가 모델 파일을 내려받고(약 100MB), 고정된 해시와 맞는지, 입력·출력 규격이 맞는지 확인한 뒤 콤마에서 직접 컴파일합니다(10~20분). 시동을 켜면 멈췄다가 다시 주차하면 이어서 합니다.
  - `WMI V11`은 upstream이 정책 파일만 따로 공개해서, 정책 파일(약 14MB)을 내려받아 기본 모델 파일의 정책 가중치만 바꿔 만듭니다. 기본 모델 파일, 정책 파일, 만든 결과 모두 고정 해시로 확인합니다. 업데이트로 기본 모델 파일이 바뀌면 만들지 않고 카드에 이유를 표시합니다.
- 주차 중에 준비가 끝나면 **다음 주행부터** 그 모델로 달립니다. 카드에 `사용 중`이 보이면 실제로 그 모델이 쓰인 것입니다.
- 기본 모델 파일은 지우지 않습니다. 다음과 같을 때는 자동으로 기본 모델로 주행하고 카드에 이유를 표시합니다.
  - 컴파일이 끝나지 않았거나, 소프트웨어 업데이트 뒤 다시 컴파일이 필요할 때(주차 중 자동으로 다시 컴파일합니다)
  - 모델을 불러오지 못했을 때
  - 주행 중 그 모델에서 오류가 나거나 잘못된 값(NaN 등)이 나왔을 때(다시 **적용**하면 다시 시도합니다)
  - 그 모델로 두 번 연속 정상적으로 시작하지 못했을 때(다시 **적용**하면 한 번 더 시도합니다)
- 되돌리려면 `CD210`을 고르고 **적용**을 누릅니다.
- 모델마다 주행 성향(차선 안 위치, 커브, 정지·출발)이 다릅니다. 실험 모델은 처음에 주의해서 확인하세요.

### 지난 주행 추천 튜닝

**도구 → 지난 주행 추천 튜닝 카드**에서 마지막 주행 로그를 분석한 조향 튜닝 추천과 모델 의도 대비 실제 주행 일치율을 봅니다.

- **언제 분석하나:** 8km/h 이상에서 3분 넘게 조향한 최근 주행을 고릅니다(주차장 이동처럼 짧은 주행은 건너뜁니다). 늘 가장 낮은 CPU·디스크 우선순위로 돕니다.
  - **상시전원:** 시동을 끄고 1분 뒤 콤마가 스스로 분석합니다(보통 2~3분).
  - **시동을 끄면 콤마도 꺼지는 경우:** 다음 시동 1분 뒤, 지금 녹화 중인 주행을 뺀 직전 주행을 분석합니다. 결과는 그 주행 중에 당근웹을 열면 보입니다.
  - 시동이 켜져도 멈추지 않습니다. **P단에서 정차 중**이면 쉬지 않고 분석하고, 출발하면 주행에 영향이 없도록 한 단계 일한 만큼 쉬어 가며(보통 5~6분) 이어 갑니다.
  - 시동이 켜져 있는 동안에는 남은 메모리가 600MB 아래로 내려가거나(주행 중 보통 약 860MB, 메모리 부족 경고는 약 360MB) CPU·GPU 온도가 75°C 이상이면 여유가 생길 때까지 기다립니다. 10분 넘게 기다려야 하면 미루고, 다음 시동 때 다시 시도합니다.
  - 진행 중에는 카드에 `37% 완료 · 로그 읽는 중(8/22 구간)`처럼 퍼센트와 진행 막대가 보입니다(3초마다 갱신). 단계는 지난 주행 찾기 → 로그 읽기 → 같은 커브 다시 돌리기 순서입니다.
  - 카드의 **다시 분석**으로 언제든 다시 돌릴 수 있습니다.
- **모델 의도 대비 실제 일치율:** 디버그 그래프 6번(초록=제어기가 요구한 횡가속, 노랑=실제 횡가속)의 두 선이 얼마나 맞았는지입니다.
  - 평균 일치율 = 1 − Σ|실제 − 요구| / Σ max(|실제|, |요구|). 요구한 회전량 중 차가 실제로 해낸 비율의 평균입니다.
  - 커브·직선 일치율 = 요구가 1.0 m/s² 넘는 커브, 0.5 m/s² 안 되는 직선에서 차이가 허용 범위(0.3 m/s² 또는 요구의 20% 중 큰 값) 안에 든 시간 비율입니다.
  - 운전자가 핸들을 잡은 시간과 8km/h 이하는 빼고 셉니다.
- **카드 보는 법:** 맨 위 결론 한 줄이 할 일입니다. `지금 설정 그대로 두세요` 또는 `이 값 하나만 바꾸세요: 횡가속 상한 35 → 40 (3.5 → 4.0 m/s²)` 둘 중 하나입니다.
  - 그 아래 **확인한 설정** 표에는 설정마다 이름, 설정 키(예: `LateralTorqueKiV`), 주행 때 값, **유지/변경**, 짧은 이유(`바꿔도 차이 없음` 등)가 한 줄씩 나옵니다. 값은 설정 화면에 입력하는 숫자 그대로이고, 괄호 안은 실제 의미입니다(예: `70 (0.70)`).
  - 줄을 누르면 설정 화면의 그 항목으로 바로 이동합니다. 변경 추천이 있으면 결론 칸의 **설정에서 바꾸기**로 가서 직접 바꾸거나 **적용**을 누르면 됩니다.
- **추천값:** 같은 주행의 커브를 콤마에서 다시 돌려(시뮬) 값을 하나씩 한 칸 바꿨을 때를 비교합니다. 대상은 횡가속 상한(`LateralAccelLimit` ±0.5), 횡저크 상한(`LatJerkMax` ±1.0), 조향 I(`LateralTorqueKiV` ±0.20), 조향 Kf(`LateralTorqueKf` ±0.10), 토크 한도 P 걸러내기(끔↔0.3초), GM 토크 증가·감소 속도(`CustomSteerDeltaUp` ±2, `CustomSteerDeltaDown` ±3)입니다. 토크 속도는 0(차 기본값, 트래버스는 증가 10·감소 15)에서 시작하고, 판다가 허용하는 한도(트래버스 증가 12·감소 25)를 넘지 않습니다. 조향 I·P·Kf·Kd는 `사용자 토크 튜닝`(`LateralTorqueCustom`)이 켜져 있을 때만 봅니다.
  - 차량 반응은 그 주행 로그에서 맞춘 모델을 씁니다. 같은 설정으로 차량 반응만 10% 바꿔 돌린 결과를 잡음으로 보고, 그보다 큰 차이만 셉니다.
  - 커브 대부분(60% 이상)에서 좋아지고 나빠진 곳이 거의 없을 때만 추천합니다. 오차가 8% 넘게 줄거나 바깥 쏠림이 3cm 넘게 줄어야 하고, 떨림·직선 오차·토크 한도 풀림·한도 시간이 늘면 안 됩니다. 아니면 **현재 값 유지**를 권합니다.
  - 조향 P는 시뮬 결과를 참고로만 보여 줍니다(시뮬이 P를 실차와 다르게 본 적이 있어서, P는 실주행으로만 판단합니다). 조향 Kd도 참고만 합니다(Kd는 센서 잡음에 반응하는데 시뮬에는 잡음이 없습니다).
  - **조향비·조향 지연**은 시뮬로 판단할 수 없어서(시뮬이 횡가속으로 돌기 때문에 조향비 차이가 드러나지 않음) 콤마가 주행하며 학습한 값과 비교합니다.
    - 조향비: 주행 중 학습된 조향비(liveParameters) 중앙값과 실제로 쓰인 값(`CustomSR`, 0이면 학습값×`SteerRatioRate`)을 비교합니다. 8% 넘게 다르면 **확인**으로 표시하고, 의도한 값이 아니면 맞출 값을 알려 줍니다. 자동 추천(변경)에는 넣지 않습니다.
    - 조향 지연: 학습된 지연(liveDelay)과 `SteerActuatorDelay`를 **참고**로 보여 줍니다. 트래버스처럼 FrogPilot 방식 NNFF 차는 조향 제어에 학습된 지연을 쓰고, 이 설정은 차선 모드의 경로 보정에만 쓰입니다(0이면 그때도 학습값).
  - 마찰(`LateralTorqueFriction`)·가속 계수(`LateralTorqueAccelFactor`)는 NNFF를 쓰는 차에서 쓰이지 않아 보지 않습니다.
  - 주행 중에 튜닝값을 바꾸면 바꾼 뒤 구간만 그 값으로 분석합니다. GM 토크 한도(`CustomSteerMax`·`CustomSteerDeltaUp/Down`)는 주행 중 0으로 되돌려도 제어기가 그 주행 동안 직전 값을 계속 쓰므로 그 값으로 봅니다. 다만 0.5초마다 읽는 값이라 1초도 안 돼 되돌렸으면 실제로 쓰였는지 알 수 없어, 바꾸기 전 구간만 분석합니다.
  - 한 번에 하나만 추천합니다. **적용**을 누르면 그 설정 하나를 바로 바꾸고, 설정 변경 기록에 `tuning_advice`로 남습니다. 시동이 꺼져 있을 때만 됩니다. 콤마가 쓰기 직전에 다시 확인하므로, 확인창을 연 사이에 시동을 켜도 바뀌지 않습니다. 더 최근 주행이 아직 분석되지 않았거나 최근 분석이 실패했으면, 예전 추천은 적용할 수 없고 카드에 그렇게 표시됩니다.
  - 시뮬은 그 주행의 조향비 설정(`CustomSR`·`SteerRatioRate`)과 GM 사용자 토크 한도(`CustomSteerMax`·`CustomSteerDeltaUp/Down`)를 그대로 씁니다. 차선 모드나 최소거리 보정처럼 시뮬이 재현하지 못하는 조향 요구가 섞인 구간은 비교에서 뺍니다.
- **지난번 변경 평가:** 이번 주행과 그 전에 분석한 주행이 튜닝값 하나만 다르면(사용자 토크 튜닝 켜짐/꺼짐도 하나로 셉니다), 두 주행의 일치율·핸들 개입·토크 풀림·추종 오차를 나란히 보여 주고 좋아짐/나빠짐/판단 어려움을 표시합니다. 도로가 다르면 수치도 달라지므로 참고용입니다.
- **데이터 부족:** 조향 3분 미만, 운전자 개입 없이 조향한 커브 3곳 미만, 저속 시내만 달려 차량 반응을 맞출 수 없을 때는 추천하지 않고 이유를 보여 줍니다. 시뮬은 GM 토크 조향 차량만 지원하며, 다른 차는 일치율과 주행 수치만 보여 줍니다.
- 시뮬에는 운전자와 모델의 재반응이 없습니다. 추천은 "다음 주행에서 시험해 볼 만한 값"이고, 효과는 실주행으로 확인해야 합니다.

### Jetson 연결·IP·온도 확인

Jetson 통합 이후 `carrot-wip`에서는 **도구 → eGPU 상태 카드**에 연결된 Jetson의
IP, 온도와 현재 연결/오류 상태도 표시합니다. eGPU를 사용한 적이 없어도 Jetson 상태를 볼 수 있습니다.
Carrot Web 접속 주소는 콤마 IP이며, 카드 안의 Jetson IP는 Jetson 관리 접속 주소입니다.
오래된 온도나 주소는 현재 값처럼 표시하지 않으므로 값이 없으면 최신 정보를 기다리는 상태인지 확인합니다.

정상적으로 Jetson 없이 내부 모델을 사용하는 대기 상태와, 활성 추론 중 연결이 끊기거나
실제 오류·고온이 발생한 경우를 구분합니다. 표시를 없애려고 실제 오류를 무시하거나 설정을 바꾸지 마세요.
Jetson만 연결된 경우 eGPU 모델 컴파일 버튼은 사용하지 않습니다.

처음 설치한다면 [한글 설치 안내](https://github.com/ajouatom/carrot-jetson/blob/main/docs/INSTALL-WINDOWS-KO.md)를
따라 설치 ZIP을 풀고 01·02 배치 파일을 실행합니다. 이미지 준비와 USB-C 수정은 자동입니다. Wi-Fi는 연결된 콤마에서 전달받으며
SSID·비밀번호 변경 때문에 SD카드를 꺼낼 필요는 없습니다. P단에서 지도 대신 주행 요약을
보여 주는 현재 동작은 유지됩니다. 설치 경로별 실물 검증 범위는 안내의 시험판 표시를 확인하세요.

### 바로 가기

- `차량 선택`: 차량 제조사와 모델을 선택합니다.
- 2026 스타리아 전기차는 `Hyundai Staria EV 2026`을 선택합니다. 기존 `Hyundai Staria 2023`과 가속페달·기어 해석이 다르며 자동으로 선택이 바뀌지 않습니다. 선택 후 재부팅하고 정차 상태에서 기어·페달 표시와 CAN 오류를 확인합니다.
- `언어`: Carrot Web 언어를 변경합니다.
- `웹 설정`: 주행 화면 구성, 영상·HUD·AR와 웹 전용 표시 옵션을 변경합니다.
- `정보`: 장치 종류, 브랜치, 커밋, 식별 정보와 네트워크 정보를 확인·복사합니다.
- `블루투스 리모컨`, `지도 검색`

### 업데이트

- `업데이트 받기`(git pull): 현재 브랜치의 새 커밋을 가져옵니다. 오른쪽에 `새 커밋 3`처럼 받을 커밋 수가, 최신이면 `✓`가 나옵니다.
- `동기화`(git sync): 원격 브랜치와 동기화합니다. 로컬 변경이 정리될 수 있습니다.
- `변경 기록`(git log): 커밋 기록을 보고 특정 커밋·브랜치로 전환하는 데 사용합니다.
- `브랜치 바꾸기`: 로컬 또는 원격 브랜치를 선택합니다.

### 기기

- `화면 녹화`: 스위치로 화면녹화를 켜고 끕니다. 녹화 중에는 경과 시간이 붙습니다.
- `재부팅`: 장치를 재부팅합니다(한 번 더 확인).
- `tmux 기록 저장`: 현재 tmux 로그를 파일로 캡처해 브라우저로 다운로드합니다.
- `tmux 기록 보내기`: 서버 로그 전송을 요청합니다.

차량 CAN 통신 오류는 현재 온로드에서 새로 수신 중인 `carState` 또는 `radarState`가 실제 오류를 보고할 때만 tmux 진단 로그를 자동 전송합니다. 이전 주행 종료 때 남은 timeout은 사용하지 않으며, 오류 확인 후 5초를 기다려 후속 로그까지 캡처합니다. 자동 전송 로그의 `CarrotException can_error queued`는 오류 원인이 아니라 진단 로그 전송이 예약되었다는 표시이며, 바로 앞의 `current onroad CAN error detected from ...`에서 판정 소스를 확인할 수 있습니다.

### 설정 백업

- `백업`·`복원`: 파일로 백업·복원
- `QR 백업`·`QR 복원`
- `복사`: 설정값 복사, `전체 보기`: 전체 값 보기

복원하기 전에 현재 값과 백업 값을 비교하세요. 다른 차량이나 오래된 브랜치의 백업은 설정 이름이 같아도 권장 범위나 의미가 다를 수 있습니다.

### 되돌릴 수 없는 작업

빨간 글씨 항목은 맨 아래에 따로 모았습니다. 모두 누르면 한 번 더 물어봅니다.

- `고친 코드 되돌리기 (git reset)`: 선택한 기준(hard/mixed/soft)으로 코드 변경을 되돌립니다.
- `캘리브레이션 초기화`: 카메라 보정값을 초기화하고 다시 보정하게 합니다. 장치가 자동으로 재부팅합니다.
- `전체 다시 빌드`: 전체 빌드와 재시작을 수행합니다.
- `영상 모두 지우기`: 화면녹화 파일을 삭제합니다.
- `로그 모두 지우기`: 저장된 주행 로그를 삭제합니다.
- `저장소 초기화`(reset repo): 저장소 연결과 브랜치를 강제로 초기화합니다.

> [!CAUTION]
> `동기화`, `고친 코드 되돌리기`, `저장소 초기화`는 로컬 코드 변경을 잃게 할 수 있습니다. 의미를 모르면 실행하지 말고, 지원 요청 시 현재 브랜치와 커밋만 `정보`에서 확인하세요.

로그나 영상을 삭제하면 Carrot Web에서 재생하거나 분석용으로 전송할 수 없습니다. 분석 요청이 예정되어 있으면 전송 완료를 먼저 확인하세요.

## 로그 화면

로그 화면에는 `대시캠`과 `화면녹화` 탭이 있습니다.

### 대시캠

- 주행별 카드와 시간 범위를 확인합니다.
- 카드를 펼치면 약 1분 단위 세그먼트를 볼 수 있습니다.
- 세그먼트를 눌러 전방 영상을 재생합니다.
- 세그먼트 메뉴에서 주행 리플레이, 로그 전송, `qcamera`·`rlog`·`qlog` 다운로드를 선택할 수 있습니다.
- `주행 리포트`는 자동·수동 주행 시간, 거리, 속도, 급가감속과 개입·경고 통계를 요약합니다.
- 체크박스와 `선택 전송`, 전체 선택 또는 범위 선택으로 여러 구간을 전송합니다.
- 오른쪽 위 로그 메뉴에서 정렬과 최근 2·5·10개 로그 빠른 전송을 선택합니다.

문제 분석을 위한 선택과 전송 절차는 [분석용 대시캠 로그 전송](dashcam-log-sharing.md)에 자세히 설명합니다.

### 화면녹화

최근 파일부터 이름, 저장 시각과 용량이 표시됩니다. 항목을 누르면 재생하고 오른쪽 다운로드 버튼으로 원본 파일을 저장합니다. 이 탭은 기존 녹화물을 보여주는 곳이며 녹화 시작·중지는 주행 화면의 `Record` 버튼에서 합니다.

## 터미널 화면

터미널은 장치의 `carrot-terminal` tmux 세션에 연결됩니다. 재연결, 화면 지우기, `Ctrl+C`, 방향키, Tab 등 모바일용 보조 키를 제공합니다.

터미널 명령은 장치에서 즉시 실행되며 준비된 도구 버튼보다 훨씬 넓은 영향을 줄 수 있습니다. 명령의 의미를 모르면 입력하지 마세요. 연결이 끊어졌다면 `Reconnect`를 먼저 사용하고, 화면의 `Clear`는 표시만 지우며 장치 파일을 삭제하지 않습니다.

### 원격 지원

`지원`은 제한 시간 동안 외부 지원자가 터미널을 볼 수 있는 지원 세션을 만듭니다.

1. 증상을 간단히 입력합니다.
2. 공유 시간을 15분·30분·1시간 중 필요한 만큼만 선택합니다.
3. 명령 권한은 가능하면 `항상 확인`을 사용합니다.
4. 지원 링크와 PIN은 지정된 지원자에게만 전달합니다.
5. 화면에 표시되는 명령을 읽고 필요한 명령만 `실행`으로 승인합니다.
6. 지원이 끝나면 즉시 `중지`합니다.

`전체 허용`과 `무제한`은 사용자가 모든 위험을 이해하고 실시간으로 세션을 지켜볼 때만 사용하세요. 링크와 PIN을 공개 채널에 올리지 마세요.

## 접속·표시 문제 해결

1. 브라우저와 장치가 같은 네트워크인지 확인합니다.
2. 장치 IP가 바뀌지 않았는지 확인합니다.
3. 주소가 `http://장치-IP:7000` 형식인지 확인합니다.
4. 공용 Wi-Fi의 기기 간 통신 차단 기능이 켜져 있지 않은지 확인합니다.
5. 페이지를 새로 고친 뒤에도 안 되면 장치를 재부팅하고 서비스가 시작될 때까지 기다립니다.
6. 지원 요청에는 장치 종류, 차량, 브랜치, 커밋, 발생 시각, 오류 문구를 함께 적습니다.

유심(셀룰러)이 꽂힌 장치가 저장된 Wi-Fi 신호의 가장자리에 있으면 Wi-Fi에 붙었다 끊기기를 반복하며 Tailscale 연결이 끊길 수 있습니다. 그래서 셀룰러 데이터가 되는 동안 저장된 Wi-Fi 신호가 30 아래면 장치가 Wi-Fi 자동 연결을 쉽니다(저장된 네트워크와 비밀번호는 그대로). 신호가 45 이상으로 10초 유지되거나, 저장된 Wi-Fi가 30초 넘게 안 보이면 다시 자동으로 연결합니다. 신호가 괜찮아도 연결 실패가 5분 안에 3번 나면 5분 쉬고 다시 시도합니다. 셀룰러 데이터가 안 되면(셀룰러로 2분 동안 아무것도 받지 못하면) 쉬지 않고, 화면에서 직접 고른 Wi-Fi 연결은 그대로 됩니다. 장치를 재부팅하면 자동 연결이 원래대로 켜집니다.

영상만 보이지 않을 때는 다른 브라우저가 스트림을 사용 중인지, 장치가 주행·카메라 준비 상태인지, 현재 브라우저가 영상 코덱과 WebRTC를 지원하는지 확인하세요.
